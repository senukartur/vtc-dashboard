### Durable client state and transport protocol

These are implementation requirements to realize the frozen contract, not existing exports or a proposed competing wire API.

1. **Connect and bind.** Show the configured service origin, authenticated account and complete first-sync scope before connection. Keep the secret in OS-protected main/service storage. Use the contract's connection route to obtain authoritative account/company/identity epoch and limits; register `clientInstallationId` through the installation route. Persist the returned binding before materialization. The permanent owner key includes origin/account/company/epoch. A new token for the same owner/epoch can resume unchanged work; another account or epoch cannot adopt it. Legacy unbound records bind once; the token does not prove who drove that history.
2. **Enumerate and observe.** Atomically establish an initial high-water boundary and durable scan run/cursor while enabling a durable material-change stream. Walk every retained eligible game trip in bounded pages, including open, partial, delivered, cancelled and closed-with-unknown-outcome records, with no age cutoff or per-trip selection. Changes concurrent with scan and changes beyond its boundary must remain discoverable after a crash. Scan and live paths share one source-trip revision allocator and material-state comparison; no duplicate revision/event is minted because both saw a trip. A source change and its durable change indication must not be separable by a crash. Persist page progress only together with durable pending work or a durable pointer guaranteeing later materialization.
3. **Freeze before send.** Read a consistent full summary and relevant stored evidence, allocate the next material revision/event ID, and commit immutable envelope bytes plus original registration/provenance/delivery run before any network attempt. Initial terminal history needs no invented start. Open refreshes use higher revisions without becoming second starts; terminal correction preserves earlier evidence. If available reads cannot establish a consistent complete context, retain uncertainty or extend the external read API under review. Never silently truncate into a complete snapshot.
4. **Schedule and send.** Separate scan/materialization from upload. Allow one HTTP upload request in flight, using bounded history/live scheduling so an initial backlog cannot starve new terminal summaries. Send one frozen v1.0 event with the contract's size/media limits; never send exports, samples, paths, process/window data or ownership/acceptance selectors. Recording, overlay and native ACK never await HTTP.
5. **Validate receipt, then clean up.** Require the expected HTTP/status pair (`202 stored` or `200 duplicate`), exact supported contract, matching event ID, valid receipt ID and first-receipt timestamp. Replays must retain the same receipt and first-receipt identities; contradictory replies are invalid. Commit local receipt/delivered state before queue cleanup or capacity release. Remote commit followed by a crash before local receipt commit replays the identical envelope and obtains a duplicate. A 2xx alone, native ACK, timeout or truncated/mismatched reply cannot release work.
6. **Persist retries and holds.** Follow the [contract error table](../contracts/telemetry-v1.md#errors-retries-and-operational-bounds). Store attempts, next eligible time and fixed diagnostics; use capped full jitter and validated `Retry-After`. Authentication/eligibility pauses owner work; permanent validation/binding/identity errors hold affected work for explicit repair/reconciliation. Unsupported version/media needs client repair, not lossy downgrade. Keep unknown HTTP errors visible. TLS/redirect failures must not forward credentials or disable validation. Restarts preserve backoff/holds; retries never rewrite frozen identity/content.
7. **Apply pressure without loss.** At 10,000 pending serialized events or 64 MiB, pause new materialization/enumeration while retaining durable source/change progress. Continue draining already frozen events when auth/network/backoff permit. Durable receipts free capacity; resume materialization automatically. Expose unsynchronized backlog separately from queued/delivered counts. Do not expire old pending work, discard source changes or block recording to meet a queue bound.
8. **Preserve copies and ownership.** A copied/restored local database preserves source identities, permanent owner metadata and original frozen envelopes/registration references. A new installation may register separately for new work, but cannot rewrite old `installationId`, `bindingId`, `databaseUuid`, event IDs, revisions or sync-run mode. Lost binding/envelope metadata requires a visible reconciliation hold. This database-copy test does not add a remote restore feature.

### Source-to-envelope projection checklist

Use the exact [snapshot semantics](../contracts/telemetry-v1.md#snapshot-fields-and-normalization) and schema rather than a renderer DTO or local export document. Each row needs a tested source reference or an explicit unavailable value at implementation time.

| Concern | Required projection and evidence |
| --- | --- |
| Identity and lifecycle | Retain `tripUuid`, game and plugin session; database UUID is provenance, not an extra dedupe dimension. Map observed delivery/cancellation distinctly from restart/gap/configuration closure. Full terminal snapshots work without a prior start request. |
| Availability | Preserve observed zero, empty display labels and unavailable reasons distinctly. Unsupported metadata stays unavailable; labels never become catalog IDs, and native API version never becomes retail build. |
| Time | Trace raw source occurrence and event sequence, checkpoint/last-known/receipt fallback, close carrier and regression clamps. Set actual start/end evidence only when supported; do not replace missing actual time with freeze/receipt/sync time or today's qualification. |
| Money | Preserve exact native decimal strings using lossless range checks: expected income u64; revenue/penalty s64. Keep unknown/documented currency basis. No Number conversion above safe integer range, mixed-currency totals or journal aggregate substituted for an outcome field. |
| Mass and distance | Preserve actual shipment mass separately from unit mass/count; planned/observed/delivered distances remain separate normalized metrics. Partial observed distance is a segment, not whole-trip distance. Real-game corroboration/tolerance needs evidence, not invented policy. |
| Mode | Unknown is none/none; known needs supported detection and non-none confidence; single-player is weak. TruckersMP module-scan claims need genuine local observation, while module/process names and paths remain excluded. This never proves driver identity. |
| Trailer and rule context | Derive context from all relevant stored configurations and intervals, following complete pagination or a reviewed aggregate API. More than ten historical configurations or fifty intervals must not produce false completeness. Mid-trip changes and unavailable/missed history require explicit uncertainty. |
| Quality and privacy | Aggregate bounded reason codes, supported fuel/damage and completeness without raw interval/event/sample upload. A value outside ordinary damage range remains anomalous evidence, not a silently clamped fact. Verify closed schema and the projection allowlist at every upload/artifact boundary. |

### P2 — Full retained history, scan restart and live overlap

### P3 — Lifecycle, ordering, replay and MySQL conflicts

- **Setup:** full schema-valid synthetic snapshots for start/complete, cancel, close without known outcome, higher/lower revision and terminal correction; P0's real target MySQL with two independently coordinated senders.
- **Action:** send start then complete; terminal before start; lower revision after higher; cancel and restart/gap close separately. Race identical events across two connections, then send changed content under an existing event ID and a second ID reusing a revision. Submit forbidden owner/role/company/accepted/exception selectors. After an authorized synthetic acceptance, submit a material correction and, where the relevant modules exist, a matching manual report/reconciliation.
- **Observe:** inspect immutable message/receipt and canonical state before/after each action through authorized test assertions. Exactly one durable source receipt/effect for a replay; conflicts preserve original evidence; lower/start messages cannot reopen a terminal trip. Delivered is not company acceptance. Confirmed decisions/totals/progress remain frozen while correction/reconciliation awaits authorized staff; accepted contribution changes once only. Missing downstream modules make those assertions PENDING, not passed by ingestion alone. No self-review bypass.
- **Evidence:** named concurrency barriers/faults, receipt equality/conflict assertions, rollback results and counts for source, canonical and safe outbox/effect records; exact command/test case and SHA. Avoid dumping rows or raw payloads.

### P4 — Offline transport, ambiguous commit and local receipt crash

- **Setup:** controllable loopback fault proxy/test transport that records safe counters only, plus client kill hooks and independent server assertion access. Keep network faults scoped to this test process.
- **Action:** disconnect before send; restart offline; reconnect. Let the server commit an event, discard its response, then restart the server/client and retry. Kill the client immediately before local receipt commit, after receipt commit/before cleanup, and after cleanup. Repeat with truncated JSON, wrong event/version/status, malformed receipt and contradictory replay receipt/time.
- **Observe:** frozen envelope bytes/IDs survive every restart. Remote-commit/lost-reply obtains `200 duplicate` with original receipt/first receipt; no premature queue deletion or second effect. Invalid ACK retains work. Persisted receipt survives cleanup crashes and capacity is released only after durable local receipt. Native recording remains responsive during all HTTP outages.
- **Evidence:** fault-point and restart counts, local/server commit-order assertions, original/retry byte equality and aggregate canonical/effect counts. Do not retain bearer headers or transport body traces.

### P5 — Retry classes, versions and transport bounds

- **Setup:** a deterministic clock/random source in the test build and controllable responses; separately exercise the actual built server's strict parser using synthetic fixtures.
- **Action:** return 429 with valid seconds/date and invalid `Retry-After`, transient 5xx/timeouts, 401/403, 400/409/413/415/422, an unknown HTTP error, invalid ACK, redirect and TLS validation failure. Restart while backing off or held. Try unsupported contract/media, invalid UTF-8, duplicate keys, unsafe numbers, oversized/deep/unknown-key input and synthetic/replay/export origin shapes.

- **Evidence:** response-class/timing/attempt assertions, parser rejection counts, hold/resume observations and safe-log canary results with versions/SHAs.

### P6 — Queue pressure, durable accumulation and drain/resume
