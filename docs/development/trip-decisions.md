# Canonical trip decisions and review

VTC-029 implements the disabled-by-default acceptance coordinator over the owning [Trips](trips.md), [Manual Reports](manual-reports.md), [Qualifications](qualifications.md), [Reconciliation](reconciliation.md), [Events](events.md) and pure [rule engine](qualification-rules.md) facades. Approved policy remains in [CONCEPT.MD](../../CONCEPT.MD); the [browser contract](../contracts/dashboard/openapi.json) preserves existing Decision operations and adds the named proposal-decision response union and optional immutable event-association proposal references described below. Frozen telemetry wire bytes are unchanged. UI, analytics consumers and notification delivery remain VTC-030/032/036.

## Classification and effective state

Uncontested open telemetry stays unassessed. Supported delivered telemetry needs positive whole-trip actual distance, actual start/completion, complete recording, normalized route/cargo/trailer identities and resolved historical qualification/rules. Proven terminal or qualification violations reject with stable reason codes. Unknown recording, lifecycle, mappings, distance or history and unresolved reconciliation route review. The coordinator does not interpret every `evaluateCompanyAcceptance` failure as a proven violation. Manual-only reports always require another authorized human, including when pure qualification checks fail.

Every human decision requires a trimmed nonblank explanation. Dispatcher, Deputy and Director have the same prohibition on reviewing any manual author in the complete canonical group, including aliases and telemetry-backed manual reports. Current identity/session/member authority is checked before receipt replay and again through transaction-scoped owning locks. Explanation text and private proposals remain in owned history; audit/outbox contain fixed codes and references only. Accepted company-trip visibility never grants access to the review/proposal/evidence workspace.

Effective decisions and pending work are separate. Late source changes, corrections and event invalidation preserve confirmed fact, outcome, reporting instant and contribution until review. Source retries return their original source receipt without a second decision. Decisions retain fact/support IDs, historical assignment/level/rule IDs, event/attendance references, reason codes, actor/time and committed attribution. Rejected proposals record `ProposalReview.reject` while returning the existing effective `Decision`; before any terminal decision exists, the additive `EnvelopeTripProposalDecision` branch returns the rejected proposal itself. Rejection does not fabricate a rejected trip decision.

## Historical attribution and supported corrections

Supported telemetry start selects historical qualification/progress and completion selects reporting. Manual gameplay timestamps remain unknown; its first acceptance captures a confirmation instant. Replays, corrections and ordinary contribution replacement retain that captured manual confirmation. A reviewed switch to telemetry explicitly replaces attribution. Missing history never substitutes the current assignment. Supplying an assignment ID alone cannot manufacture an actual start or a historical interval. Numeric production limits and company timezone remain administrator-owned launch configuration.

Resolution proposals support only the existing `ResolutionInput`. Catalog selections are validated against published same-game/kind facts. Manual evidence must already belong to the effective group and remain owner-ready; telemetry corrections can cite retained structured source evidence without inventing screenshot requirements. No manual gameplay dates or arbitrary violation waiver is accepted. Distance/mass/time corrections use exact normalized relational values. Staff-supported telemetry time uses the internal `staff-resolution` basis and `staff_resolution` contribution attribution rather than masquerading as an original source event.

`trip_facts.kind` separates source and derived rows. Source rows retain their non-null unique message relation and immutable source bytes. Derived rows have no direct message/receipt; restrictive base-fact, resolution-revision and retained source-message references establish provenance. `trip_resolutions` retains the immutable proposed changes/explanation/evidence references. Readers reconstruct quantities, pins, ordered trailers and times from relational columns and validate direct base/proposal/source consistency. A second correction retains the preceding reviewed fact and original source identity without recursive lineage traversal. Contributions keep their actual FK to the effective fact, including derived revisions, after raw payload expiry.

## Browser operations and concurrency

The existing routes are implemented:

- `GET /api/v1/trips/{tripId}/review`, `/proposals`, `/proposals/{proposalId}` and `/qualification-assignments`.
- `POST /api/v1/trips/{tripId}/decisions`, `/resolution-proposals`, `/proposals/{proposalId}/decisions` and `/event-association`.

Commands use Origin/CSRF, strict closed schemas, `If-Match: "vN"`, permanent actor/operation/key receipts and keyed normalized fingerprints. Exact replay still checks current authority; changed input conflicts. Proposal detail returns the current canonical ETag, while approval additionally checks the exact immutable proposal revision, base trip/fact and current supporting source/history/event versions. A changed supporting epoch requires fresh review. Correction-request IDs remain distinct from proposal IDs. Signed keyset cursors bind actor/session/access epoch and query scope, with the existing one-to-one-hundred page bounds.

Ownership discovery precedes current company/sorted member/qualification preparation, sorted complete canonical group locks, then review/proposal/contribution/evidence locks. Current locking reads avoid reusing an older repeatable-read snapshot after waiting for a peer. Decision time is sampled after preparation. A decision transaction changes canonical state, immutable decision/history, synchronous contribution replacement/progress proof checks, calendar-year retention metadata, safe audit/outbox and permanent receipt together. Whole-transaction retry is limited to classified deadlock/lock-wait failures after rollback. Ambiguous COMMIT is returned without blind callback retry; the same durable command key resolves a lost response.

Any independent adjudication advances a separate Trips marker. An obsolete merge reversal conflicts even when a newer decision retains the same outcome/fact/reporting with another explanation. Accepted primary results survive merge; alias credit is removed once. Valid reversal restores supported independent results with monotonic contribution versions. Qualifications reevaluates affected old/new promotion proofs and emits its existing review alert without automatic demotion.

## Event participation and durable work

Event association is stored separately from source evidence and validated through the Events facade. Only current confirmed actual attendance and a matching prescribed load can bypass the corresponding ordinary mass/trailer/ADR restrictions. RSVP does not authorize an exception; lifecycle/evidence/distance/history remain required. Changes to confirmed associations use proposals. Manual form event selections enter the same association seam after the immutable revision and references exist.

API composition prepares qualification state whenever reconciliation or acceptance is enabled. Telemetry refreshes reconciliation before assessing the resulting canonical root. Manual assessment runs after its immutable revision, source pointer, evidence references and pending state persist. Correction requests and merge/reversal use narrow caller-transaction callbacks, without recursive public commands.

Event definition/attendance/cancellation writes advance a dedicated Events-owned trip-assessment generation and pending-invalidation marker. Enabled composition atomically enqueues the reference-only `trips.reevaluate` job and acknowledges that current generation. While adjudication is disabled, Events changes only its own current row; later enabled maintenance seeds at most twenty-five pending events per pass before ordinary bounded linked-trip fanout. RSVP advances the existing public change sequence but leaves the trip-assessment generation unchanged, so it cannot obsolete required work or grant an exception. Generation fences discard obsolete work. An indexed event/trip keyset fans out at most twenty-five links per effect, and continuation commits with page effects. A Trips-owned indexed pending-assessment marker records source/group changes even while adjudication callbacks are disabled. Successful assessment clears only that marker without inventing aggregate history or decisions. A persisted catch-up generation/cursor processes at most twenty-five dirty roots per page; a completed generation restarts only after an indexed bounded dirty probe finds work. Stale generations and duplicate/reclaimed jobs cannot duplicate effects. Existing queue leases, effect receipts, retries and disabled-kind pausing apply. No first outbox subscription or analytics/notification consumer is introduced. `trip.decision_changed` v1 uses canonical aggregate version and only `{decisionId, contributionVersion}`. Proposal review also atomically appends `trip.proposal_reviewed` v1 with only proposal/reviewed-revision references.

## Activation, migration and rollback

`TRIP_DECISIONS_ENABLED=false` is the default. Enabling requires Identity, Catalogs, Trips, Qualifications, Manual Reports, Events and Reconciliation plus a distinct stable sixty-four-hex-character `TRIP_DECISIONS_KEY`. Keys cannot be reused from another configured feature. API and worker must use the same reviewed configuration; production numeric settings are not supplied by fixtures.

Migration `0014_mighty_the_hunter` adds decision/proposal/work/association/receipt/catch-up storage, the Trips derivation substrate, adjudication/dirty markers, Events support-generation bookkeeping and staff-resolution enum extensions. Published `0000`–`0013` SQL/snapshots/journal prefix remain unchanged. The reviewed generated migration folds new-table constraints/indexes into parent-first creation and installs the expanded fact shape in one ALTER. Drain writers for the entire operation. MySQL DDL implicitly commits; interrupted application remains sticky and requires a consistent restore or reviewed forward repair, never automatic replay/stamping.

Before the first extended write, the additive schema remains compatible with source-only writers while acceptance is disabled. After derived facts/current pointers or staff-resolution attribution exist, pre-VTC-029 binaries assume a non-null source-message join and cannot interpret the active data safely. Disabling HTTP alone does not erase those facts. Rollback requires drained writers and a reviewed compatible artifact or consistent pre-activation restore/forward repair, preserving all committed domain data according to the authorized recovery procedure. Do not promise arbitrary old-binary rollback.

Prepared grants live in `deploy/development/trip-decisions-grants.prepared.json`, separate from hosted activation grants. Default FULL development rehearsal seeds only an explicitly guarded synthetic allocation, then uses real restricted runtime acceptance/replay/derived correction and a separate restricted worker catch-up/duplicate pass. Both roles must be denied source/history mutation and DDL. Narrow worker column updates permit required current-state locks/revision changes, not administrative account changes. The existing approved automatic development pipeline releases successful main-CI artifacts and invokes the locked migrator, so merging this additive migration can cause its automatic schema application through that pipeline. The prepared VTC-029 grants, stable key, enabled API/worker configuration and hosted feature activation remain separate authorized steps; this card does not change or dispatch that pipeline or claim current hosted activation.

TripProposal optionally exposes nullable `eventAssociation` with immutable `eventId`, `eventRevisionId` and nullable `attendanceRevisionId`. Event association proposals capture these safe references through Events at creation; later definition/attendance changes do not rewrite proposal readback. Review must display the selected event and retained revisions, then use the current canonical ETag. Current support guards fence obsolete approval. No RSVP reasons or attendance notes are included. Older responses and fixtures without this additive field remain valid.

Authorized reviewer GET refreshes the supporting-fact epoch/work and may advance the canonical version when supporting state has changed since the last assessment. It does not decide the trip or replace credit, audit or outbox effects. Authority is checked inside the same transaction before the refresh; denied requests roll back all owning projections/work. This freshness side effect makes the returned ETag authoritative for subsequent commands.

Reconciliation captures immutable apply/reverse snapshots, response versions and safe correction events after its same-transaction search/assessment effects settle. The search continuation epoch matches that final projection. Reversal retains monotonic adjudication markers; old snapshots without the marker treat it as zero while retaining all independent-decision fences.
