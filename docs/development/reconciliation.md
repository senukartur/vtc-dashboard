# Trip reconciliation (VTC-026)

[The approved concept](../../CONCEPT.MD), [card scope](../planning/mvp-trello-backlog.md#vtc-026) and unchanged [browser OpenAPI](../contracts/dashboard/openapi.json) govern this module. Reconciliation links evidence and replaces contributions; VTC-029 still owns acceptance and adjudication, and VTC-030 owns UI.

## Activation and matching

Apply additive migration `0013_modern_moon_knight` explicitly. Existing `0000`–`0012` migration bytes remain unchanged. Enable identity, trips and qualifications, then `RECONCILIATION_ENABLED=true` with an independent random 32-byte hexadecimal `RECONCILIATION_KEY`. Manual evidence commands additionally require the manual module; reconciliation fails closed for a manual group if its private evidence facade is unavailable. API and jobs composition use the same source/group facades. Startup never migrates or accepts trips.

The four optional matching settings must be configured together: positive `RECONCILIATION_RULE_VERSION`, nonnegative integer `RECONCILIATION_START_TOLERANCE_MS` and `RECONCILIATION_END_TOLERANCE_MS`, and canonical exact nonnegative `RECONCILIATION_DISTANCE_TOLERANCE_M`. Their values are operator decisions; fixtures establish no production tolerance. Omission disables tolerance-dependent automatic matching. Persisted rule versions cannot be reused for another configuration hash. Rule identity also pins the matcher algorithm version.

Production telemetry storage calls synchronous discovery on its existing authenticated transaction. Manual submission calls it after immutable revision, evidence references, current revision and pending state are persisted. There is no queue subscription or first-subscription bypass. Exact replay returns the permanent existing source-message receipt without another match/effect, including after merge, reversal and raw expiry.

Matching uses local owner/game, exact canonical route/cargo identities, verified actual start/completion and comparable whole-trip actual distance. It uses integer milliseconds and scaled decimal arithmetic without floating point. Labels/locales, receipt time, planned distance and measured segments cannot prove identity. All same-owner/game roots are searched in deterministic order up to the technical discovery bound; undated manual reports have no receipt-time cutoff. Discovery overflow and incomplete group evidence prohibit automatic linking. Each immutable candidate records rule/search identity, group versions, source fact revisions, completeness and reasons. Each ingestion rebuilds the bounded owner/game candidate graph so a later overlapping source invalidates earlier uniqueness assumptions; pagination filters current rule and fact/group versions.

Automatic linking requires one fully supported candidate and reciprocal uniqueness after complete discovery. Distinct identities from one provider never match automatically. The frozen telemetry v1 authenticates its submitter but cannot attest who drove legacy unbound history; the matcher records `gameplay_owner_unproven` without adding a payload field or treating age/backfill mode as proof. The current manual contract has unknown actual times, so ordinary manual/telemetry similarity remains `review_required` even with one candidate. Explicit trusted same-owner/game/version linkage and reviewed reconciliation remain available. This conservative current outcome does not establish future-provider or legacy ownership attestation.

A staff command can correct a reviewed genuine duplicate with distinct canonical identities, including evidence from one provider. This does not relax automatic same-provider separation or convert two distinct journeys into duplicates. Every reviewed merge requires current authority, both versions and an explanation.

## Canonical groups and projection

Trips owns flat `alias_of` membership. Original trip, source-trip, provider/event/revision, immutable fact, report, revision and screenshot-reference ownership never moves. Source/fact reconstruction remains pinned to original identity. All aliases resolve to one same-owner/game root; chains/cycles are rejected by owning operations. Source arrival, explicit targets, list/detail/status, private projection, correction, retention and contribution validation use effective groups. Lists/counts exclude aliases; an authorized old ID resolves to its current canonical summary. Company readers receive only the accepted public summary; current owners/reviewers receive private group evidence. Reconciliation detail exposes safe IDs/versions/state, never private explanations or raw snapshots.

Quality selection chooses one coherent supported snapshot. It preserves known values, including zero, without summing distances/fuel or combining contradictory trailer/rule/time contexts. Equal-quality supported conflicts and incomparable snapshots require review. History retains the selection rule, selected fact/source record, per-field source/catalog pins and alternatives. An accepted primary keeps its reviewed fact/reporting/attribution; later changes set correction pending. An accepted secondary requires choosing an accepted primary; an unassessed or rejected primary is rejected without changing either result. Both accepted inputs retain the primary reviewed fact/reporting/attribution even when the evidence differs. A merge never creates a new acceptance decision.

## Commands, locking and reversal

The approved routes are `GET /api/v1/reconciliation-candidates`, `POST /api/v1/reconciliations`, `GET /api/v1/reconciliations/{reconciliationId}` and `POST /api/v1/reconciliations/{reconciliationId}/reversals`. They require current `trips.review`; writes also require same-origin CSRF and a UUID idempotency key. Reversal requires its strong reconciliation ETag plus both current original trip versions from the detail DTO. Signed keyset cursors bind session/access epoch, scope and rule hash. Every affected manual author is forbidden from applying/reversing their own group, including Director and Deputy.

Permanent reconciliation-specific command receipts retain fingerprints and exact results without Identity's expiring-command TTL. A changed key input conflicts. Authority/author guards still run on replay. A lost COMMIT response is never automatically retried; a later explicit identical command resolves its durable receipt. Only classified deadlock/lockwait failures are retried, after whole-transaction rollback and with the existing bounded retry policy.

The coordinator calls Qualifications preparation before trip mutation: company, sorted current members, qualification state/assignments, sorted canonical group rows, then reconciliation/source/contribution state. Contributions validate the selected fact belongs to the locked effective group with the same owner/game. Replacement uses captured authoritative manual confirmation timing, removes all alias credit and recomputes affected old/new periods and promotion proofs without demotion. Private history, membership, contributions, permanent receipt, audit and safe correction outbox commit together.

Apply history captures before/after group membership, reviewed independent projections, source fact set, credits and quality provenance. Reverse requires the current membership to match that apply snapshot; overlapping dependent reconciliations must be reversed first. It restores independent states using new monotonic trip/contribution versions. New source facts remain under original identities and trigger review when independent states are restored; accepted facts remain frozen. Later independent adjudication or changed reviewed projection makes an obsolete reversal conflict instead of overwriting a decision.

Screenshot projection and review/deletion fences span every original member. Retention checks the group's latest decision and renewed review, with the full minimum calendar year. A deleting evidence generation cannot be reattached/reopened by reconciliation. Filesystem I/O remains outside these transactions. Raw telemetry expiry checks the effective root and retains permanent replay identities/facts.
