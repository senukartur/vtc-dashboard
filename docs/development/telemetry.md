# Personal telemetry credentials and durable ingestion

[VTC-023](https://trello.com/c/h9cPLb6I) implements the server side of the frozen [v1.0 transport](../contracts/telemetry-v1.md). It reuses the [canonical source/trip foundation](trips.md), including immutable source messages, RFC 8785 hashing, permanent ownership, normalized facts and transactional outbox. A receipt confirms delivery; company decisions, contribution totals and notifications remain their owning modules' work.

## Activation and recovery

`TELEMETRY_ENABLED=false` is the default. Activation requires enabled identity, external identities and trips, explicit migration `0009_slimy_exiles`, reviewed runtime grants and a separate random 32-byte hexadecimal `TELEMETRY_CURSOR_KEY`. Startup does not migrate, seed or activate anything. `TELEMETRY_IP_PER_MINUTE` and `TELEMETRY_GLOBAL_PER_MINUTE` are required deployment choices (example 600 and 6000); both must be integers, IP at least 60, global at least IP and each at most 60000. These are technical admission settings, not measured capacity or company allowances. The maximum keeps scaled credit counters within unsigned INT capacity.

Runtime needs SELECT/INSERT/UPDATE on telemetry tokens, commands, installations and limits, alongside the existing identity/external/source/trip/catalog/outbox grants used by those facades. No runtime DDL or DELETE grant on immutable source/history is required by ingestion. Identity invalidation also requires UPDATE on token rows while telemetry is enabled. Production deployment tooling does not yet grant/enable this module. An operator must review those grants, exact trusted proxy, HTTPS, header/query/body redaction, database capacity and restore before explicit activation; merely merging code leaves ingestion disabled. Never collect bearer headers, token replies, raw telemetry or authenticated screenshots/traces in diagnostics.

The additive migration creates four InnoDB tables with exact binary keys, millisecond UTC dates, restrictive references and durable unique registration/command identities. Published 0000–0008 remain unchanged. Apply with the existing explicit migrator. MySQL DDL implicitly commits: interrupted rollout leaves the runner's sticky applying marker; follow [consistent restore or inspected forward repair](persistence.md#partial-ddl-recovery-runbook), never blind replay or a claimed transactional DDL rollback. Back up the migration ledger and all token/installation/source/trip/outbox tables together. Losing bindings/receipts cannot be repaired by minting new source identities.

## Browser token lifecycle

GET/POST `/api/v1/me/telemetry-tokens` and DELETE `/api/v1/me/telemetry-tokens/{tokenId}` require the current active session and `trips.submit_own`, equally for Trainee and Driver. Writes require exact Origin, session-bound CSRF and UUID Idempotency-Key, including DELETE. Issuance also requires a verified current Steam link. Bearer tokens cannot invoke these session operations.

Issuance generates 256 random secret bits. Only SHA-256 of the secret and a nonsecret exact token ID are persisted, with fixed ingest scope, local owner/company, captured Steam and access/identity/credential epochs, label, creation, last successful use and revocation times. The secret is returned after commit once. Issuance command records contain fingerprint/key/token ID only. A repeated key returns 409 `SECRET_ALREADY_ISSUED` with caller-owned token ID in `error.details[].ownResourceId`; changed input returns `IDEMPOTENCY_CONFLICT`. A lost reply or uncertain commit must be recovered using that same key, then revoke the known token and issue a replacement with a new key. The server cannot recover or replay the secret.

Rotation is issuance of a replacement followed by revocation of the old token. There is no separate rotate endpoint or invented expiry. List pages are bounded keyset pages using the existing safe TokenInfo DTO; signed cursors bind member/session/security epochs/limit. Secrets/hashes/Steam IDs never appear in token lists. Last use changes only after successful connection, registration or committed event receipt, including a valid duplicate.

Identity injects an optional same-transaction invalidation port. Deactivation, reinstatement, access/credential invalidation and actual Steam link changes eagerly revoke credentials with the domain/audit/access event; callback failure rolls everything back. Existing revocation time is preserved. Disabled telemetry never accesses absent token tables. Synchronous captured-epoch/link checks prevent revival across disable/re-enable intervals; discovering stale credentials persistently revokes them before permitting status or source work. Historical source ownership never changes with Steam or token replacement.

## Frozen transport and transactions

GET `/api/telemetry/v1/connection`, POST `/installations` and POST `/events` below that prefix require bearer authentication only. Cookies provide no fallback. Connection advertises contract and limits plus authoritative local account/company/identity epoch. Installation retries use exact owner/company/epoch/clientInstallationId uniqueness and return stable server IDs; another account receives distinct registration. Same-epoch old bindings remain valid after token rotation, allowing retries of unchanged frozen envelopes. Old-epoch work stays held for reconciliation.

Admission authenticates against authoritative company/member/Steam/token locks and charges persistent shared limits before body parsing. The receipt transaction rechecks authentication and binding, invokes `trips.storeInTransaction`, updates last use and commits before ACK. Lock order is token lookup without lock, company/member and Steam through owning facades, token lock/recheck, installation, source/trip. Identity changes serialize through the same company/member locks. A classified duplicate-key rollback allows one bounded fresh resolution with auth/binding repeated; unknown COMMIT is never automatically retried. Browser availability uses safe 503; frozen errors use the v1 fixed codes and safe request ID.

The raw transport accepts at most 65536 bytes including whitespace, fatal UTF-8, depth at most 16, no duplicate decoded object keys, finite safe numbers, closed schemas, exact v1.0, uncompressed application/json with UTF-8 only. It reuses the frozen source adapter for field-specific uint64/s64 strings, mode/lifecycle invariants and UTF-8 field bounds. Invalid raw input cannot pass through ordinary JSON.parse first. Source identities remain independent of database copy, token and installation. Synthetic/export/replay producer shapes and client ownership/acceptance fields are rejected.

New committed messages return 202 `stored`; exact replays return 200 `duplicate`, with identical source-message receipt ID, event ID and persisted first receipt time. The immutable source message is the only receipt record. Normalization/current projection completes synchronously in the same transaction and its existing safe outbox records retain future effects; there is no artificial ingestion job or second inbox. Older revisions remain evidence, terminal-before-start does not reopen trips, and confirmed results remain frozen pending review. Source times, backfill mode, occurrence provenance, quantities, catalog IDs and unknown availability retain their original meaning. No company credit or live activity is generated here.

## Persistent admission and verification

Events use a shared token bucket of 60 requests/minute with burst 10. Connection/registration share a separate token control bucket with the same technical defaults. Token (when authenticated), IP and global buckets charge in that order; denial stops downstream charges so one exhausted credential/source cannot drain shared budgets. Revoked/ineligible credentials still return authentication/permission errors when rate budgets are exhausted. Malformed/media/version attempts consume admission; denied attempts cannot create receipt/last-use updates. Counters use MySQL, survive another process/restart and refill by elapsed server milliseconds; a backwards clock does not move the stored refill time backwards. Keyed IP hashing uses 512 fixed anonymous source slots plus one global bucket, preventing unbounded anonymous row creation; collisions conservatively share a budget. At most two token bucket rows exist per retained credential. Revoked credentials/history are retained, so operators must monitor total token/history volume. Limits serialize shared counters and current identity locks; hosted throughput/latency has not been established.
