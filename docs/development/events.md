# Events and voluntary participation

VTC-034 implements the Events backend APIs from [the browser contract](../contracts/dashboard/openapi.json) and [product policies](../product/mvp-policies.md), scenarios 1, 2, 5, 14, 20–22, 30, 31, 33 and 39. The [VTC-035 workspace](event-workspace.md) provides rendered RU/EN event workflows; VTC-029 owns trip adjudication; VTC-036 owns subscriptions, notifications and reminders. Source integration does not activate a hosted service or apply a live migration.

## Activation and routes

Events is disabled by default. Set `IDENTITY_ENABLED=true`, configure identity as documented in [identity](identity.md), then set `EVENTS_ENABLED=true` and an independent cryptographically generated 32-byte lowercase hexadecimal `EVENTS_CURSOR_KEY`. The key must differ from identity, mail, admission, catalog, trip, qualification, telemetry and manual-report keys. Missing/invalid enabled configuration fails startup; disabled Events mounts no routes. Local Compose passes both Events settings. The API installs the Events service and produces durable work. Notifications-disabled composition omits its notification subscription and handlers. Enabling Notifications with its prerequisites wires the owning producer callbacks, subscription and handlers through shared composition; maintenance, routing and execution run in the separately invoked jobs CLI, not in API requests. Catalog selections additionally require the enabled catalog adapter and published same-game facts; null selections can operate without catalogs.

| Route | Access and result |
| --- | --- |
| `GET /api/v1/public/events`, `GET /api/v1/public/events/:eventId` | Anonymous; explicit public DTO, members-only detail is 404 |
| `GET /api/v1/events`, `GET /api/v1/events/:eventId` | Current `company.read`; both visibility classes |
| `GET /api/v1/me/upcoming-event` | Nearest scheduled accessible event, independent of RSVP, or null |
| `GET/PUT /api/v1/events/:eventId/my-response` | Current `events.respond`; own private reason only |
| `GET /api/v1/events/:eventId/participants` | Current member; participating members' safe summaries only |
| `GET /api/v1/events/:eventId/decliners` | Current member; declined members' safe summaries only, never reasons (VTC-058A) |
| `GET /api/v1/events/:eventId/response-counts` | Current member; `{participating, declined}` totals only, no unanswered count or identities (VTC-058A) |
| `POST /api/v1/admin/events` | Director/deputy `events.manage`; 201 |
| `PATCH /api/v1/admin/events/:eventId` | Full EventInput replacement under definition ETag |
| `POST /api/v1/admin/events/:eventId/cancellation` | Private nonblank reason, immutable cancellation |
| `GET/PUT /api/v1/admin/events/:eventId/attendance` | Director/deputy; collection ETag, private RSVP reasons and latest staff notes |

Browser mutations require the existing authenticated Origin/CSRF policy and a UUID idempotency key. Commands with a body use JSON. Commands except creation require strong `If-Match: "vN"`; omitted precondition is 428, malformed input 422, stale version 412, conflicting idempotency input 409. Dispatcher alone cannot manage events or read others' reasons. Public serializers exclude participants, attendance, member visibility, load prescriptions and private notes. Public event existence is filtered before detail serialization; list pagination never includes private rows.

Event input includes game, server, organizer display text, description, route and meeting location text, canonical city IDs, meeting/start/end instants, visibility and optional prescribed cargo/mass/trailer IDs. Display text never becomes identity. UTC dates must be canonical millisecond `Z` instants, calendar-valid, with meeting <= start and supplied end >= start. Technical string/batch/page limits are transport/storage bounds, not company business policy. Exact nonnegative mass fits DECIMAL(38,18) and canonical decimal wire form. The event's command actor is server-derived and distinct from organizer display text.

Lists have bounded chronological keyset pages, start-time/UUID tie breaking and `period=upcoming|past` (default upcoming). Signed cursors bind visibility, period, actor/session/access epoch and a fixed UTC period boundary, preventing a moving clock from changing the next page's period. Participant, decliner and attendance pages bind event and their own scope; attendance pages also bind collection version. Tampered/cross-scope cursors fail 409. Current access is rechecked even with a valid old cursor. Rescheduling can change live list ordering; cursors are not a frozen snapshot of all event content. All instants remain UTC across DST; VTC-035 renders user timezone labels.

## Published routes (VTC-124)

Set `EVENTS_ROUTE_ENABLED=true` on the API and jobs runner after applying migration `0028_faulty_caretaker`. This setting defaults to false and requires both Events and Catalogs. The published [Stage 2 contract](../contracts/dashboard/README.md#stage-2-foundation-vtc-132-step-1) is selected by body shape for creation and edit. Immediate publication accepts the complete definition with `draft` omitted or false. Edit uses the complete Stage 2 definition and its current ETag. These commands default to English labels and accept `?locale=en` or `?locale=ru`. Member detail and cancellation select the staged response with explicit locale while the setting is enabled. Public detail accepts `?locale=en` or `?locale=ru` in either mode. With the setting off it returns the legacy response, and with the setting on it returns the Stage 2 response. Guests can decode either closed public schema from the same request. Detail without locale and commands using legacy bodies keep their legacy responses. Member list and upcoming reads select the staged response with an explicit locale while the setting is enabled. Public lists and RSVP use the legacy contract. Leadership can select Stage 2 attendance with `?view=stage2` independently of this setting. Both attendance reads use the same collection ETag.

Successful authenticated `GET /api/v1/me` includes `X-VTC-Events-Stage2: 1` when the staged route backend is enabled. The JSON still uses the closed `EnvelopeSelf` schema. The existing account read exposes the header through `useSession().eventsStage2Enabled`. The value defaults to false while checking, after session loss or an error, and for a response without that exact header value.

The current active organizer is locked through Identity before the event and its safe nickname is copied into the immutable definition. Only the member projection includes the organizer ID, load prescription and response counts. Catalogs validates depots by row ID, game and the corresponding city. New selections require visible depot, company and city rows. The same unchanged selection can remain after hiding. Manual DLCs must be distinct same-game canonical IDs. A previously selected manual DLC can remain after hiding. City and depot DLCs are resolved by ID, deduplicated with manual DLCs and returned in stable ID order with each applicable source. City, cargo and trailer labels use the requested locale and English fallback. Depot and DLC names and codes are canonical, and depot labels come from their company. The route projection reads no company logos. Cover availability remains false until the media feature supplies it.

Optional exact decimal kilometers preserve zero and use null for unavailable distance. Absent description, route and meeting text use empty storage text and appear as null on the Stage 2 wire. The legacy serializer uses an em dash for empty text and a legacy edit echoing that display value keeps the existing empty field. A staged edit carries forward any omitted description, route or meeting text. Explicit null clears the corresponding field. A legacy edit carries compatible structured values, clears depots for changed side cities or game, clears distance for a city or game change, clears manual DLCs for a game change and unlinks an organizer whose display text is replaced. Cancellation copies the current route details and manual DLCs. Older revisions remain readable with null structured fields and may derive DLCs from their existing city references.

The detail marker and manual DLC rows are written with the definition, current pointer, command receipt, audit and outbox in one transaction. The staged input has its own fingerprint domain. Replays recheck current actor authority and use the original revision, original own-response and attendance references and original ETag. Staged commands also retain safe aggregate response counts at commit. Catalog labels and derived requirements use the current catalog. Cancellation uses one receipt for both serializers.

Route alerts compare ordered city and depot IDs for a successor with a detail marker, including revisions produced by the legacy editor while the setting is on. Earlier successors keep the route/meeting text comparison. Writer, classification and bounded prefix repair use the same rule. Start changes and cancellation retain their precedence, and recipients remain the participating audience at the original change sequence. See the [deployment and compatibility procedure](../operations/development.md#published-event-route-activation).

## Drafts and publication (VTC-125)

`EVENTS_DRAFTS_ENABLED` defaults to false and requires `EVENTS_ROUTE_ENABLED=true`. Successful authenticated `GET /api/v1/me` includes `X-VTC-Events-Drafts: 1` only when the draft endpoints are enabled. The existing `EnvelopeSelf` JSON stays closed. The current session exposes the separate capability through `useSession().eventsDraftsEnabled`. See the [activation procedure](../operations/development.md#event-draft-activation).

| Route | Event manager action |
| --- | --- |
| `GET /api/v1/admin/events` | Browse published definitions by start and ID. With drafts enabled, `period=drafts` browses active drafts by latest save and ID. Both filters have actor-, session-, access epoch- and locale-scoped cursors. |
| `POST /api/v1/admin/events` with `draft: true` | Reserve an event ID and save a sparse draft at version 1. |
| `GET/PATCH /api/v1/admin/events/drafts/:eventId` | Read an active draft or replace its editable fields under the draft ETag. Omitted and null selections clear prior values. |
| `DELETE /api/v1/admin/events/:eventId` | Discard an active draft under its ETag. The request has an empty body. |
| `POST /api/v1/admin/events/:eventId/publication` | Publish the saved draft under its ETag with an empty JSON object and optional response locale. |

Draft input validates each supplied value, including exact nonnegative quantities and relationships among the supplied times. Canonical catalog selections require a game, and a selected depot also requires its side's city. Unchanged hidden selections can remain in drafts. Publication checks the full definition, active organizer and current catalog visibility using the immediate publication rules. The same ID and metadata retain the existing gallery and media version.

Draft reads and commands use the same current company, sorted actor/organizer and session authority as other Events commands, then lock metadata and the draft. Draft commands store closed, versioned response snapshots with their result and ETag in the same transaction. They bind the effective precondition and publication locale. Exact retries return the original snapshot with fresh request metadata after current actor authorization. A new command against a published or discarded draft conflicts. Draft create and immediate publication reject conflicting reuse of a key on the shared create route.

Publication commits the first scheduled event and immutable `published` revision at version and sequence 1. It attaches the published metadata pointer, writes route and DLC history and produces the existing event transition and pending work in the same transaction. Draft saves and discard have safe audit entries. They remain outside member/public reads, reminders, RSVP, attendance and trip support. [Event registry](../contracts/dashboard/events.md)

## Transactions, versions and immutable history

Every command locks company, sorted actor/target members and current session through Identity's owning `eventContextInTransaction` facade, then event/current child state and its durable command identity. No Events query reads Identity tables directly. The company lock serializes current access and commands; this favors correctness for the single-VTC MVP over independent per-event write throughput. Authoritative time is sampled after those locks. The shared bounded transaction retry retries only classified MySQL deadlock/lock-wait errors after explicit rollback. An uncertain COMMIT remains uncertain and is never automatically retried; a later caller retry with the same key consults the durable receipt and current authority.

Definition version, each member's response version, and attendance collection version are independent. The unanswered initial response is version 1; its first change is version 2. A response never changes the definition ETag, another member's response ETag, or attendance ETag. Attendance GET/PUT share a collection namespace beginning at 1. A repeated equivalent response produces no extra response history, audit or outbox effect. Repeated explicit attendance decisions are retained as new staff decisions. Every effective mutation advances a separate per-event change sequence, used for ordered history and later consumers.

RSVP accepts unanswered, participating, or declined with a nonblank private reason. At `now == revised startsAt`, RSVP closes and actual attendance opens. A later start reopens response editing and preserves prior answers; an earlier start closes it using the revised value. Cancellation closes response/attendance mutation and excludes the nearest-event result. Unanswered or non-attending members receive no automatic penalty. Staff actual attendance is separate from RSVP, accepts 1–100 distinct known members atomically after start, and retains actor, time and private note.

Migration `0011_tearful_infant_terrible` adds eight owned tables: current Events/Responses/Attendances, immutable definition/response/attendance revisions, immutable catalog pins and permanent command references. Published `0000`–`0010` bytes stay unchanged. UTC datetime(3), binary application IDs, exact mass and restrictive event/member/catalog foreign keys preserve history on account departure. Current revision pointers and response aggregate IDs are validated by the transactional service rather than cyclic foreign keys: definitions, response and attendance revisions must belong to their current event/member, and current pointers are assigned in the same transaction. Published history has no deletion API or cleanup. Treat direct runtime history writes/deletes as outside this facade's contract.

Creation uses a server-generated UUID. Durable command uniqueness is actor + route + target discriminator + key; creation's target discriminator is the client key, other routes use the event ID. Independent administrators can reuse a key without sharing event IDs. A keyed canonical fingerprint covers precondition and input without storing private reasons in ordinary command results. Exact replay reconstructs the original DTO from immutable definition/own-response/own-attendance references and returns its original version. Current permission/session checks still precede replay. Legacy receipts retain safe IDs and versions. Private reasons and notes remain in owned history. Domain, history, safe audit, receipt and outbox share one caller transaction and roll back together.

## Catalog and integration facades

`Catalogs.selectionsInTransaction` validates at most four same-game selections against the current lists. An unchanged selection may reference a row that is now hidden; a new selection of a hidden row fails with `CATALOG_SELECTION_HIDDEN`. Labels are read from the current row, so a rename shows in the event. Unknown kinds/games/IDs fail 422, and non-null selections without an adapter fail 503.

The service exports these bounded owning seams:

- `history(actor,eventId,afterSequence,limit)` requires current event management and returns immutable private definition/response/attendance streams plus `nextAfterSequence` for each stream. `afterSequence` is exclusive (initially 0); `limit` is 1–100 definitions, responses or complete attendance decision batches per stream (default 25). Each stream selects one extra entry/batch only to detect continuation; lookahead rows are not returned or consumed. A non-null stream continuation is the last emitted sequence: pass it as `afterSequence` for that stream's next page; null means that stream is exhausted at this read. Paginate streams independently rather than taking the maximum sequence across streams. Attendance first selects bounded distinct sequences, then returns every revision for those sequences, ordered by sequence/revision ID; the command's 100-member batch bound limits each page to `100*limit` attendance rows. History reads retain current authorization and the event lock across selection and fetch. No public browser history endpoint is introduced here.
- `definitionInTransaction(tx,revisionId)` returns safe immutable identity/version/start/status/change-order facts. `generationInTransaction(tx,eventId)` separately locks and reads only the current safe definition identity/version/start/status/visibility/change sequence so a later consumer can fence cancelled or superseded generations; it exposes no private content.
- `recipientsInTransaction(tx,eventId,changeSequence,afterMemberId,limit)` uses a latest-prior-revision SQL anti-join and member keyset to reconstruct participating recipients immediately before a definition change. It returns only member IDs, at most 100. Future consumers must recheck current membership/resource access at effect creation/delivery/read.
- `associateInTransaction(tx,actor,{eventId,memberId,game,eventRevisionId?,attendanceRevisionId?})` participates in a caller transaction and permits the owner or current trip reviewer/event manager. It validates access, same game, event revision membership and attendance ownership. Coordinators acquire Identity/company/member locks before trip locks and retain that same transaction. It returns immutable references and conservative attendance mapping: actual attended -> rule `confirmed`, not_attended -> `declined`, missing -> `unconfirmed`. RSVP alone never yields `ConfirmedEventContext`. Invalid/mismatched references fail safely; cancelled events cannot authorize an exception. Superseded definition/attendance references retain identity with `reviewRequired=true` and no usable confirmed context. Accepted decisions keep their stored references for staff review rather than being silently rewritten.

Only a current actual-attended decision tied to the current definition returns a usable `ConfirmedEventContext`; prescribed load matching remains the existing pure qualification matcher. The coordinator still checks prescribed cargo/mass/trailer against the trip and owns actual acceptance/contribution replacement. Events does not accept a trip, count progress or emit a reminder.

## Safe events and recovery

Closed schema-v1 `event.changed`, `event.response_changed` and `event.attendance_changed` contain only safe event/definition/revision/member IDs, category and change sequence. Schema-v1 definition event categories are created/updated/cancelled. Draft publication emits created and stores a published definition revision. Response and attendance use their own monotonic aggregate/version namespaces. Attendance batch history is recovered through event/change sequence, not by assuming its representative last revision describes every member. [VTC-036](notifications.md) subscribes to definition/response changes for generation-aware notifications. Events retains its own pending marker while notifications are disabled and supplies bounded recipient, current reminder eligibility and correlated eligibility-query ports. Reminder items/counts immediately exclude obsolete definitions or RSVP, even before maintenance; private response fields remain Events-owned. Material start/route delivery retains its original change-sequence audience across cosmetic successors and bounded pages. Events maintains exact material-transition anchors across cosmetic and equal-value return revisions and provides a batched safe current projection; a missing legacy prefix is repaired through at most 25 indexed forward definitions, independently of reminder generation; superseded material live alerts are suppressed without deleting saved history. Attendance remains outside that subscription. See [event registry](../contracts/dashboard/events.md).

Apply the additive migration through the locked runner and [partial-DDL recovery procedure](persistence.md#partial-ddl-recovery-runbook). Startup never migrates or seeds. MySQL DDL implicit commits remain relevant; never rewrite the published prefix or clear a sticky applying marker to replay blindly. The fixed synthetic reset drops Events children before catalog/identity parents. The persistence suite rehearses exact eleven-migration prefix upgrade with sentinel/checksum preservation; recovery retains its distinct partial-DDL and lost-receipt cases with thirteen current migrations. No live migration, grants, production retention deletion or deployment is performed by this card.

## Event media

The [Stage 2 media operations](../contracts/dashboard/README.md#stage-2-foundation-vtc-132-step-1) use a collection ETag independent of event definition, RSVP and attendance. Uploads reserve one of ten slots and track the private generation before writing. The reservation is invisible until bounded full decoding succeeds and the command rechecks manager authority and the original collection ETag. Exact retries use the original ETag, key, accepted MIME and bytes. They return the same media ID and its current safe state, or 404 after removal. Captions, order and cover changes use closed versioned receipts and replay the committed result under current manager authority. Admin reads include ready and accepted processing items first, with room for the most recent rejected uploads.

The jobs worker generates a JPEG thumbnail up to 480 × 270 pixels without enlarging the source. It strips source metadata from the thumbnail and preserves the original bytes for authorized full-size requests. Thumbnail attempts and cleanup have separate durable jobs and generation fences. On each pass, bounded scans recover expired tentative reservations, turn terminal processing failures into rejected uploads, and reclaim retired generations and staging files. If the private root is unavailable at startup, the pass reports a storage error and pauses only the media jobs. Media attempts resume after storage is available. No image route is served from the web root. Every request rechecks current event access, and all gallery and image responses use `no-store`.

Apply migration 0028 through the existing locked migration runner before activation. With `EVENTS_ENABLED=true`, set `EVENT_MEDIA_ROOT` to an absolute, dedicated persistent directory outside the web and manual-evidence roots. Set `MANUAL_MAX_FILE_BYTES`, `MANUAL_MAX_PIXELS` and `MANUAL_UPLOAD_TIMEOUT_MS` to the approved image limits. Manual Reports can stay disabled. Provision the same filesystem for the API and jobs worker. For Compose, use a private override to pass the variable and mount the separate volume. On Linux the runtime owner needs directory mode 0700 and write access for staging, hard-link promotion and removal. Keep the root in the backup and restore plan alongside the database, and run the normal bounded jobs CLI regularly.

Before enabling the root, grant the API and worker only the needed media operations. Both read draft and published lifecycle rows. The API reads, inserts and updates `event_metadata`, `event_media` and `event_media_generations`, reads and inserts `event_workflow_commands`, and appends thumbnail jobs through the existing queue privileges. The worker reads and updates media and metadata, and reads, inserts and updates generations. The worker uses the existing queue and receipt privileges. The application never removes the key tombstones or uses runtime DDL. Leave `EVENT_MEDIA_ROOT` empty to disable the routes and pause both job kinds without supplemental grants. Keep the root and database state for reactivation.
