# Review, repository rules and dependency hygiene

[VTC-010](https://trello.com/c/czpF65wG) owns this process. Read [AGENTS.md](../../AGENTS.md) and the [Definition of Done](agent-rules.md#definition-of-done). Product approval, independent review, passing CI, merge and production acceptance are separate evidence.

## Review before merge

Use one card and scoped branch at a time. The [PR template](../../.github/pull_request_template.md) records behavior, exact candidate SHA, actual checks, review, impact/rollback and pending gates. [CODEOWNERS](../../.github/CODEOWNERS) routes all files to `@senukartur`; ownership is not independent approval.

Authentication, permissions, migrations, qualification rules, deduplication/reconciliation and deployment changes require review independent of the author, appropriate to risk and covering the final SHA. A separate reviewer can be an authorized independent agent; self-review is insufficient. Record its identity/source, scope, limitations and finding dispositions. Obtain a human specialist or stop when the available review cannot assess the risk. The solo-maintainer path has zero mandatory GitHub approval votes, avoiding an unavailable second-human requirement without waiving independent review.

Before every merge, inspect available automated-review comments, inline comments and unresolved threads. Fix supported actionable findings or record an evidence-based rejection/explicit deferral; accepted blocker/major findings prevent delivery. After a fix, rerun affected checks and obtain independent review covering the new SHA. Resolving a conversation alone does not establish a fix. Require green **Required CI**, a current base comparison, resolved conversations and independent review; use normal guarded merge without bypass. If independent review or required checks are unavailable, leave the PR pending.

## Automated review selection

The owner disabled native GitHub Copilot code review on 2026-10-18. A fresh read-only `Protect main` ruleset and effective-main readback confirmed that the active ruleset no longer includes its rule; [main.json](../../.github/rulesets/main.json) reflects that state. Historical Copilot findings below remain evidence for earlier VTC-010 fixture runs, not a current review request or merge gate.

The owner selected the Claude Sonnet 5.5 advisory workflow as the automated PR review path. It remains supplementary to independent review and **Required CI**. Review only public-safe synthetic material; identify a private-value finding by location/category without repeating it. Follow [CI diagnostic restrictions](ci.md#safe-diagnostics).

The owner requested restoration of the former Claude advisory Action as the automated PR review path. It does not replace independent review or Required CI. The automatic workflow starts after the repository's `CI` workflow completes for a pull request. CI runs when a PR is opened (including as a draft), synchronized, reopened, or marked ready for review; this lets a draft that later becomes ready receive its advisory review. Claude reviews only open, non-draft, same-repository PRs targeting the default branch, excludes PRs authored by Dependabot, and skips a run unless its recorded head still matches the current PR head. `workflow_run` loads this workflow from the default branch. The job checks out the PR's trusted default-branch base SHA and reads the PR diff through GitHub; it does not check out or execute PR code or download run artifacts. The on-demand trigger accepts an `@claude` mention from a repository owner on an open same-repository PR targeting the default branch, excludes PRs authored by Dependabot, and checks the target and head before checkout or authentication. It also reads the trusted base tree; the diff supplies changed PR content.

The workflow passes the configured `CLAUDE_CODE_OAUTH_TOKEN` secret as its Anthropic credential and does not pass a second API-key credential. Each review job grants `GITHUB_TOKEN` `contents: read` and `pull-requests: write`; the token can do more than publish review comments. Neither review job can write commit statuses: the required status comes from a separate job (below), so a prompt injection in the Claude step cannot forge the merge gate. Claude's tools are scoped to repository reading and PR inspection: `.git` is explicitly denied to `Read`, `Grep` and `Glob`, and Bash `git` commands are disallowed. A pinned `github-script` step validates the structured summary and findings, rejects output matching common credential/private-key/email patterns, neutralizes generated mentions and links, verifies that the PR head has not changed, and publishes one advisory `COMMENT` review attached to that exact commit. Inline findings are filtered against changed lines in the PR diff so an invalid location cannot suppress the summary. The model cannot publish inline comments directly. Prompts and tool allowlists prohibit code changes and project execution. Repository content remains untrusted input; these restrictions and pattern checks do not prove protection from prompt injection or guarantee that every generated public comment is safe. Review only public-safe synthetic material and identify private-value findings by location/category without repeating them.

### Required review status

The owner made the automatic review a merge gate on 2026-11-04 ([VTC-075](https://trello.com/c/8IWITRy5)). Before that, auto-merge could merge a PR as soon as **Required CI** passed, because the review starts only after CI completes. A separate `Required review status` job then publishes an `Advisory review` commit status on the reviewed PR head. It alone holds `statuses: write`, runs no PR-controlled input and uses only the review job's validated target, its publish outcome and its result:
- **success** when the review was published for that head;
- **failure** when the review or its publication failed, or the review job was cancelled or reached `timeout-minutes`; re-run the workflow run to retry;
- **success** with "advisory review not run" for Dependabot PRs, which the review excludes. GitHub restricts the token of Dependabot-triggered `push` and `pull_request*` runs, not `workflow_run`, and lets `permissions` raise it ([Dependabot on Actions](https://docs.github.com/en/code-security/dependabot/troubleshooting-dependabot/troubleshooting-dependabot-on-github-actions)); this is expected but not yet seen on a hosted run. Confirm the status on the first Dependabot PR. If it is missing (a 403 in the status job), Dependabot PRs stay blocked until the exemption is published another way; meanwhile the owner can merge them with the [admin bypass](#main-rules-and-application) or restore the previous snapshot without `Advisory review`;
- **nothing** when the PR head had already changed before the review started; the newer run decides. If the head changes while the review runs, publication fails and the old head gets **failure**, which no longer affects the PR. A status job that itself fails or is cancelled publishes nothing, so the PR stays blocked until the run is re-run.

The main ruleset requires that status from GitHub Actions (app `15368`) next to **Required CI**. Inline findings then block merge through the resolved-conversations rule until they are resolved. The review stays advisory in content. Findings outside the diff appear only in the summary and do not block. Fork PRs get no automatic review and stay blocked, and an `@claude` on-demand review does not publish the status. Automatic reviews share a concurrency group only per PR head, so a late CI event for an older head cannot cancel the review of the current head; repeated CI runs of the same head still cancel each other. Status jobs of one head queue in their own group without cancelling, so the newest run publishes last. A Claude outage blocks merges until the run is re-run, unless the owner merges with the admin bypass.

Apply order: merge the workflow change first, because `workflow_run` loads it from main, and only then apply the ruleset. Open PRs at that moment need their review re-run to receive the status.

The configured model is `claude-sonnet-5-5`, as listed in Anthropic's [official model documentation](https://platform.claude.com/docs/en/models/sonnet-5-5/overview); usage is subject to the chosen credential's subscription or API billing limits. No secret value, account entitlement or fixed per-PR cost is asserted here.

Earlier Copilot availability and billing evidence is retained in linked historical reviews and fixture records. Copilot is disabled as an active reviewer; no current Copilot entitlement or billing claim is made.

## Main rules and application

The snapshot preserves deletion/force-push protection, PR requirement, resolved conversations and zero mandatory approvals. Strict **Required CI** is bound to the verified GitHub Actions app ID `15368` and enforced on branch creation. Since VTC-075 the snapshot also requires the [`Advisory review` status](#required-review-status) from the same app. The owner applied it on 2026-11-05, and a readback showed both required checks. At the same time the owner added one bypass actor: the repository Admin role (`RepositoryRole` 5) in `pull_request` mode. It lets the owner merge a PR when the advisory review is unavailable, for example during a Claude outage. It applies only to merges through a PR, so deletion and force-push protection still hold for everyone. GitHub grants the bypass to every actor with the Admin role, including any admin-level token, not to the owner personally. Owner-only use is therefore a policy, not an enforced restriction: agents and the delivery workflow must not use it even when their credentials would allow it, and wait for every required check or leave the PR pending. A bypassed merge leaves **Required CI** and `Advisory review` unmet, so the owner records each one in the PR: the reason and the missing checks. [CI](ci.md) produces that stable aggregate; no advisory reviewer replaces it. Committing JSON alone does not apply hosted settings.

For future changes, an authorized maintainer must first fetch the current ruleset and compare its name, conditions, rules and bypass actors with the reviewed snapshot. Stop and reconcile concurrent changes before updating it. Review the exact request body independently, then update that existing ruleset through repository Settings → Rules → Rulesets or `PUT /repos/senukartur/vtc-dashboard/rulesets/25301218` with the JSON file. Read back both the ruleset and `GET /repos/senukartur/vtc-dashboard/rules/branches/main`; retain public-safe evidence of the effective rules. [GitHub's rules API](https://docs.github.com/en/rest/repos/rules) documents these operations. Access limitations must remain explicit; never compensate by bypassing protection. The owner's recorded PR-merge bypass above is the one documented exception.

For acceptance, use an independently reviewed temporary synthetic PR marked **DO NOT MERGE**. Exercise a defect caught by existing tests and request the configured advisory review; record the exact finding/check SHA. With the PR non-draft and other merge conditions accounted for, observe server-reported blocking by failed **Required CI**. Never attempt a merge of defective code to test protection. Close the fixture unmerged, retaining links and the actual outcome; a successful review run without an actionable finding is not seeded-defect proof.

The [supported ecosystem/options reference](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference) documents these options. No auto-merge is configured. Scheduled execution, cross-directory grouping and generated PRs require hosted evidence after the configuration reaches the default branch; YAML alone does not prove them.

Review dependency/image changes through a scoped PR and the normal checks. Keep immutable Action/image references and the shared runtime pins synchronized; review release provenance, compatibility and relevant MySQL/browser behavior. Do not accept a bot PR merely because it is generated. Security fixes need prompt triage; deferrals require an owner, affected range/reason, compensating measure where relevant and a dated revisit in the linked card/PR. Do not publish private registry credentials or audit payloads.
