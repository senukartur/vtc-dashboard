# UI and localization foundation

[VTC-012](https://trello.com/c/oFcRxl5S) provides reusable presentation conventions in the existing React/Vite SPA. Product policy remains in [CONCEPT.MD](../CONCEPT.MD); wire values and authorization rules remain in the [browser contract](../contracts/dashboard/README.md). This does not implement authentication, company workflows or domain endpoints.

## Entry points and composition

- `/status` retains the real, cancellable `/health/ready` request. Only matching HTTP 200/`ready` and HTTP 503/`not_ready` responses are accepted. Invalid responses and transport failures show a safe translated error; retry stays disabled during a request. No failure falls back to synthetic success.
- `/foundation` is a public presentation shell with explicitly fictional examples.
- `/foundation/member` demonstrates member composition, visibly labeled as a synthetic preview. It grants no access and makes no session/permission claim. VTC-013 and feature owners must integrate authoritative identity and permissions before live use.

`app/` owns providers, route recovery, navigation and shell landmarks. `features/foundation/` owns example forms, lists, chart composition, translations and mock responses. `shared/ui/` contains small composable primitives: Button/Slot, Input/Label/FieldError, a native Select, Card, Badge, Table, Radix Dialog, underline Tabs, SegmentedControl and a responsive chart container. Native select controls preserve platform keyboard behavior. Tabs wraps radix-ui Tabs (tablist/tab/tabpanel, arrow/Home/End roving focus, panels labelled by their tab); callers name the list. SegmentedControl is project-authored: a named native fieldset group of buttons where exactly one carries `aria-pressed="true"`; each option stays in the normal Tab order and responds to click/Space/Enter. Dialog callers supply the title, description and translated close control. Radix provides focus containment, Escape and trigger restoration; mobile navigation closes when a link is activated.

Initial entry preserves the skip link as the first keyboard stop. Ordinary hashless route changes focus the main landmark. An unmodified internal mobile-navigation click records its origin location, exact path/search/hash destination and trigger. The intent survives a still-pending origin-location effect, then is consumed once at the next destination, including same-path and fragment navigation. At the exact destination the shell explicitly focuses a connected visible trigger without scrolling; for non-fragment navigation it falls back to main when the destination removes or hides that trigger. Selecting the current route and pressing Escape also preserve trigger restoration. Modified or non-self-target clicks create no intent. Fragment and skip navigation retain their existing targets. The phone More sheet records the same intent with More as its trigger; Sign out from the sheet, or a sheet whose trigger is no longer visible, moves focus to main, and widening the viewport to 768 pixels or more closes the sheet.

Use a single page heading, labeled sections, a skip target, visible focus and the compact control scale below. Tables become labeled row cards below 760 pixels. Long labels wrap; canonical UUIDs may wrap without truncation. Status requires readable text. Chart geometry is accompanied by an exact table and explicit units/reporting timezone. Motion is disabled for the chart and reduced-motion preferences are respected.

Browser journeys capture public and member menu visibility before opening each dialog because their responsive breakpoints differ. Navigation journeys cover role-grouped sidebar visibility for trainee, dispatcher, driver+dispatcher and deputy director (unit tests cover every role, including driver-only and director), breadcrumb/title/current markers in RU and EN, user-menu keyboard use, routing and language switching without losing input, the desktop icon rail, sign-in landing and deep-link return, compact row metrics and contrast, and sign-out recovery. At 390×844 they also cover the phone bottom bar for trainee, dispatcher, role-less and deputy-director members in RU and EN (names, visible labels, current markers, 40-pixel targets, label fit, content and focus clearance, the emulated bottom safe-area inset and viewport-fit restoration on leaving the workspace) and More sheet semantics (focus containment, Escape, trigger restoration after routing, language switching without losing input); at 768×1024 and 1280×800 they confirm that no bar is shown. Regressions cover immediate activation after a history commit as well as current-route, Escape, fragment, modified-click and unavailable-trigger behavior.

### Compact control scale

Owner decision (2026-10-31, [VTC-043](https://trello.com/c/uFgAfWVc)): after reviewing the running UI, the owner approved a compact rework and replaced the former 44-pixel control rule. Contrast and accessibility gates are unchanged; only the size rule changed. Later layout cards build on this scale.

Button, Input, native Select, Badge and Table accept `size="xs" | "sm"`; `sm` is the default and is carried by the base class, so raw `.button` links and native `<select>` elements are compact without opting in. Variants live in `shared/ui/variants.ts` and emit semantic classes whose metrics come from CSS custom properties:

| Primitive | `sm` (default) | `xs` |
| --- | --- | --- |
| Button | min-height 30px, padding 4px 12px, radius 6px, 13px text | min-height 24px, padding 2px 8px, radius 5px, 12px text |
| Input / Select | min-height 32px, 10px inline padding (select keeps room for its arrow), radius 6px, 13px text | min-height 24px, 8px inline padding, 12px text |
| Badge | 11px text, padding 1px 6px, radius 4px | 11px text, padding 0 4px |
| Table | 13px cells, 8px padding, 12px muted headers | 12px cells, padding 4px 8px |
| SegmentedControl | 2px container padding, items 30px (`size="sm"`) | items 24px (default) |
| Tabs | 32px triggers, 2px primary-blue underline on the active tab | — |

Use `xs` only for actions repeated inside a table cell or list row; everything else stays `sm`. Under `@media (pointer: coarse)` the height tokens (`--control-h-sm`, `--control-h-xs`, `--field-h-sm`, `--field-h-xs`, `--target-min`) all become 40px and inputs/selects/textareas use 16px text to avoid zoom on focus. Bare buttons and inline targets (catalog/trip/qualification disclosure summaries, checkbox rows, admin status filter links and contact/account/error-summary links) use `--target-min`: 30px on fine pointers, 40px on touch. The selected admin status filter adds a border and a 2px focus-blue inset underline so selection is not conveyed by background colour alone. Sidebar, desktop and dialog navigation links also use `--target-min`; hover uses the `--surface-hover` background with foreground text, and the current link keeps the stronger selection style.

The owner-selected compact direction uses a dark page and inset fields (#0E1525), darker sidebar/topbar (#0A101D), card surfaces (#121A29) with structural borders (#1E2A40), hover and active surfaces (#182238 / #1E293B), a blue primary action (#2563EB) and visible focus/link blue (#60A5FA). Text is #F3F4F6, secondary #CBD5E1 and muted #94A3B8. Accepted, pending and rejected semantics retain separate green, amber and red treatments with readable text/symbols. Page titles use 18px/600, section headings 13px/600, body text 13px and secondary text 12px; the 14px root keeps rem-based spacing stable. Spacing is 4px-based: gaps are 12px and card padding is 14px; cards use an 8px radius and controls 6px. The existing Yukon Union wordmark remains; a permitted company master asset is still pending. Private reference artboards were not accessed, so pixel parity is not claimed. CSS custom properties define surface, foreground, border, accent, error, focus, spacing and radius. Public/member pages put useful controls and data states before supplementary analytics; no production totals or business thresholds are inferred from examples.

Enabled input, select, outline-button and segmented-control boundaries use a separate neutral #7C8799 token to maintain at least 3:1 contrast against their adjacent surfaces, including the outline-button hover state. The mockup's #334155 field border measures about 1.7:1 on cards, so it is only a structural `--border-strong` token. The mockup's #64748B muted grey measures about 3.7:1 and is not used for text or placeholders. Structural borders retain the approved darker tokens. Browser regressions measure computed text, placeholder and control-boundary contrast rather than relying on token names, including pressed/unpressed segments, active/inactive tabs, the active-tab underline and an `xs` button.

## Locale, identity and exact values

Core messages live in `i18n/core/resources.ts`; feature messages live beside the feature in `translations.ts`. Initialization uses explicit `core` and `foundation` namespaces, Russian by default and English fallback. `html.lang` follows the selected language. The preview intentionally includes one missing Russian namespace key in its explanatory dialog to exercise fallback. Foundation-preview preferences remain memory-only. [VTC-017 account preferences](account.md) use the authenticated identity API.

`shared/formatting.ts` converts canonical nonnegative decimal strings by shifting base-10 digits, formats integer parts with `BigInt`, and keeps every fractional digit. It never converts canonical distance/mass to JavaScript Number for display. Meters become kilometers and kilograms become tonnes; `null` is unavailable and `"0"` is zero. Invalid decimals fail closed. ISO UTC instants require a supplied display timezone; invalid dates/timezones show unavailable. Chart Number conversion is separately bounded and used only for approximate geometry; exact accessible values remain strings.

Display timezone changes timestamps only. Company bucket dates and `reportingTimezone` are taken from the analytics response. The synthetic UTC response is not approved company launch configuration. `CatalogLabel.requestedLocale`, `renderedLocale` and `englishFallback` determine presentation, including an explicit English fallback marker. Select values remain canonical UUIDs with the catalog revision unchanged on locale switches.

## Synthetic injection and future integration

`createFoundationMocks(locale)` returns fresh typed generated-contract responses. `FoundationPage.mockFactory` is a narrow injection seam for examples; it does not intercept requests or replace live failures. Provenance is `listTrips:empty`, `listTrips:error-403`, `getCatalogEntity:english-fallback` and `getCompanyAnalytics:success` in the [reviewed structural examples](../contracts/dashboard/examples.json). Available/partial lists add fictional long labels and a null distance while retaining generated DTOs. Unit tests validate every response against `@vtc/contracts/runtime` schemas. No competing DTO, private evidence, real identity, database seed or provider payload is introduced.

The content selector explicitly exercises loading, empty, error, forbidden, partial and available states. Forbidden removes all previously displayed example rows/catalog/analytics. Retry and reset have safe local behavior. The local note form uses React Hook Form and Zod validation, preserves input after a simulated recoverable failure, prevents duplicate pending submissions and reports a local-only confirmation. It sends no request and performs no company command. Its delay is only a presentation exercise.

Invalid submission focuses the note once through the form's invalid-submit handler. Automatic error focus is disabled so delayed validation work cannot interrupt subsequent Tab/Shift+Tab progress. A browser regression advances queued zero-delay validation work after Tab, then checks focus and the ordinary input/pending/failure/retry/success flow; the original natural keyboard journey remains separate.

Future feature owners replace the example seam with reviewed contract transport/query flows, pass cancellation signals, partition query keys by effective inputs/access scope, and clear sensitive caches when access changes. Server queries must filter unauthorized data; hiding UI is not permission enforcement. Do not reuse local confirmation as evidence that a server command committed.

## Provenance and checks

The minimal primitives and responsive chart structure are manually adapted from [shadcn/ui](https://github.com/shadcn-ui/ui/tree/d2fba50ee5b9113008b5bb908563527b7efd2f27), exact commit `d2fba50ee5b9113008b5bb908563527b7efd2f27`, `apps/v4/registry/new-york-v4/ui/{button,input,label,card,badge,table,dialog,chart}.tsx`. The verbatim MIT notice is retained in [third_party/shadcn-ui/LICENSE](../../third_party/shadcn-ui/LICENSE). No remote generator, dashboard template, icon set, game asset or new logo is incorporated. `components.json` and matching TypeScript/Vite aliases describe this workspace; copied components still require project-specific review.

Used exact dependencies are radix-ui 1.8.1, class-variance-authority 0.7.1, clsx 2.1.1, tailwind-merge 3.7.0, react-hook-form 7.90.0, Zod 4.6.7, Recharts 3.10.1 and react-is 19.3.1. `@hookform/resolvers` is omitted: its 5.9.1 optional ajv-formats peer conflicts with the root's 3.0.1. RHF calls `Zod.safeParse` directly; root peers, runtime pins and release-age policy stay intact.

Run `pnpm check`, `pnpm build`, `pnpm test:unit`, and the isolated `pnpm test:local` described in [testing.md](testing.md). Browser coverage preserves the real MySQL readiness smoke and separately labels controlled negative readiness responses. Synthetic journeys cover three viewport projects (390×844, 768×1024, 1280×800), RU/EN, complete states, form recovery, focus and exact chart/timezone values. The `/foundation` compact-controls example is measured per project: fine pointers assert the 30/32/24px heights and 13px body, 18px/600 title, 12px table header and 11px badge text; the touch-emulating mobile project must match `(pointer: coarse)` and every measured control is at least 40px. Segmented-control and tab keyboard semantics are checked in RU and EN. Success screenshots are saved through Playwright output paths under ignored `.local/testing/`; actual rendered review remains required. Local/CI passes do not establish independent review, merge, staging acceptance or live feature integration.

Comparable pinned native Vite builds measured an initial single 839.81 kB JavaScript bundle (258.51 kB gzip). Loading foundation routes and their chart with React.lazy/Suspense reduced entry plus eager preloads to 424.29 kB (entry 254.46, primitives 94.45, dialog 74.66, runtime 0.72); foundation and chart code load separately. This measures shipped bytes, not end-user latency. Suspense keeps a translated loading state inside the useful shell; the route error boundary offers a full reload to retry a failed module download. No caching/security policy or chunk-warning threshold is relaxed.

The dark shell and font-license link bring that same entry-plus-preload measurement to 425.56 kB (entry 255.73, unchanged shared chunks); foundation 108.56 kB and chart 306.84 kB remain lazy. M PLUS Rounded 1c core subsets are separate requests of 24452 (400), 24440 (500) and 25000 (700) bytes, at most 73892 bytes per page against the former single 193056-byte variable font; extended Latin/Cyrillic subsets (40292, 40420 and 40720 bytes) load only for text in their ranges. Text such as city names (Łódź, Plzeň) also loads `ext`: 400+500 core+ext total 129604 bytes, and all six files 195324 bytes, slightly above Onest. The complete license adds 4351 bytes. The system fallback remains usable while the font loads or when its download fails.

The reusable AppLayout composes public horizontal navigation, the synthetic member preview or the live member workspace. `app/navigation-model.ts` is the single route source: App.tsx builds `/account/*` routes from it, and the sidebar, breadcrumb and `document.title` (`{page} · Yukon Union`) read the same route metadata. The live sidebar shows a New report action for members who can submit their own trips, then groups (My work, Company, Review, Management) filtered by current server capabilities; detail routes mark their parent item as current. On desktop it collapses to a 56px icon rail with labels kept as accessible names, persisted in local storage. The topbar shows a breadcrumb, the nearest-event chip, the notification bell and the user menu (Radix DropdownMenu). The user menu holds the driver profile, Account and security, connections, the RU/EN language choice, the public site and sign-out; the banner language select appears only where no authenticated user menu exists. From 768 to 1050 pixels the same groups open in the existing keyboard-accessible navigation dialog and the user menu moves into the topbar.

Below 768 pixels ([VTC-045](https://trello.com/c/T3yL8Kud)) an authenticated member gets a fixed bottom bar (`nav` "Main sections") with Overview, My trips, a third slot and Events, plus More. The third slot is the accent New report tile for members who can submit their own trips, otherwise Dispatch (labelled Review) for reviewers, otherwise it is omitted; short visible labels sit inside fuller accessible names. Current sections carry `aria-current` from the same route metadata; More never does. More opens a bottom sheet (Radix Dialog) with the remaining permission-filtered groups as "Main navigation", then an account block outside that landmark: identity, the user-menu account links, a per-session RU/EN segmented choice (the saved preference stays on the Account page), the public site and sign-out. Count badges and a Notifications entry are not added. The phone topbar is one row with the short YU wordmark (full name kept as its accessible name), the breadcrumb shown as the page title (the group stays for assistive technology only) and the notification bell; the nearest-event chip keeps its row below, and the topbar user menu and navigation dialog are hidden. Anonymous, unavailable and signing-out shells keep the dialog and banner language select without a bar. Live workspace pages add `viewport-fit=cover` to the viewport meta and restore the original on leaving; the shell's inline padding, the bar and the sheet follow `env(safe-area-inset-*)`, and the shell's bottom padding, the root `scroll-padding-bottom` and the notification toasts clear the 56-pixel bar plus the bottom inset. The `/foundation/member` preview keeps its earlier sidebar and invents no account, role, notification or production data. Dedicated screenshots capture keyboard skip, form-error, dialog and navigation focus; browser checks measure computed text/placeholder/primary/disabled contrast and sidebar placement, supplementing actual rendered review.

M PLUS Rounded 1c is self-hosted as six WOFF2 subsets made from the Regular, Medium and Bold TTFs of google/fonts commit 84efd8ad78c3710ad14bd909e3bc407151885628. [Its provenance](../../third_party/m-plus-rounded-1c/README.md) records input/output sizes and hashes, the fontTools 4.67.0 command, the full-width punctuation excluded from the subsets and the rendered symbols that intentionally use the system fallback (… U+2026, whose source glyph has centred dots, and ▤ ◷ 🔒, which the font lacks). The [SIL OFL 1.1 copyright/license](../../third_party/m-plus-rounded-1c/OFL.txt), SHA-256 2f6ab907c3fc803a369cf3a25f906b8e6b528fa176dde716de6aba2e3895c504, is imported as a separate Vite asset linked in the localized footer, so the complete notice accompanies built/deployed font bytes. Each weight has a `core` face (Basic Latin, Latin-1, basic Cyrillic U+0400–045F, common punctuation and the arrows and symbols the app renders, such as ← → ↗ — № ● ✓ ✕) and an `ext` face (Latin/Cyrillic Extended) with matching `unicode-range`, font-display: swap and the `"M PLUS Rounded 1c", system-ui, sans-serif` stack. The family has no 600: CSS 600, 650, 700, 750 and Tailwind semibold/bold render Bold, 500 and font-medium render Medium, 400 renders Regular, the former 550 table header uses 500, and `font-synthesis-weight: none` prevents faux bold. Computed values stay unchanged, so the h1 still reports 600. Metric overrides (ascent 99.3%, descent 30.5%, line gap 0%) keep the previous 263-unit space above the 730-unit cap height and the previous descent; accented capitals such as Å paint above that 993-unit ascent (1013 units in Regular, 1037 in Bold; Onest reached 981 at weight 700 against its 970), and explicit line heights keep control sizes. Digits share one advance per weight, so `tabular-nums` aligns without a fallback font. Runtime font requests stay on the application origin; no external font service or new package is used. Browser checks verify same-origin core loading below the former font size, lazy extended loading, Bold/Medium/Regular face selection, rendered symbols drawn from the core face, tabular digit alignment, exact deployed license bytes and usable Cyrillic fallback after controlled failed font downloads. A unit test reads the subset cmaps and checks the declared ranges, documented sizes/hashes and that every non-ASCII character in the web sources is covered or a documented fallback. Existing conservative font/license caching remains unchanged.
