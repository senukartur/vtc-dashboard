# Qualification history and confirmed progression

[VTC-028](https://trello.com/c/yrGcnx2g) implements audited per-game qualification configuration, assignment history, synchronous authoritative progress and explicit Director/Deputy confirmation. [VTC-031](https://trello.com/c/JsaqSNN2) adds the protected RU/EN workspace at `/account/qualifications`. The pure [rules engine](qualification-rules.md) remains separate from persistence. VTC-029 owns adjudication; notification transport remains separate work. VTC-025/026/034 supply manual evidence, reconciliation and attendance facades; their activation/integration gates remain explicit.

## Activation and launch configuration

`QUALIFICATIONS_ENABLED=false` is the default. Enabling the existing qualification routes requires `IDENTITY_ENABLED=true`, `TRIPS_ENABLED=true`, explicit migrations, and a separately generated random 32-byte hexadecimal `QUALIFICATIONS_CURSOR_KEY`. It must differ from identity, trip, telemetry, catalog, mail and admissions keys. Catalog allowlists also require the catalog facade and published canonical entities of the correct game and kind. Missing dependencies fail closed. Startup never migrates, seeds or supplies company numeric values.

The migration creates only eight structural levels: Trainee, Driver III, Driver II and Driver I in each game. Names are configurable; codes/order are fixed. There are **no published default rules or numeric promotion thresholds**. An authorized administrator must publish the actual company configuration before launch. Configuration audit uses a registered qualification subject with the changed level ID, separately from its actor. Shared audit/outbox contain no private rationale. Rules are typed registered `max_mass`, `allowed_trailer_types` and `allowed_adr_categories` values, never executable expressions. A publication stores immutable rules, thresholds, actor, reason, publication time and effective time. Omitted `effectiveAt` means the server publication instant; a supplied value must be at/after publication and strictly after previous effective versions. Retroactive publication and duplicate effective instants fail. Existing confirmed decisions/proofs remain unchanged.

Promotion requires both a non-null count threshold AND a non-null exact actual-distance threshold. Either unset value is ineligible. Driver I is terminal. The old native checklist's knowledge-test wording does not add an exam, tenure, cargo-damage, reputation or other MVP metric. Explicit confirmation is still required even after both configured thresholds pass.

## Assignment and historical attribution

Assignments are real half-open UTC millisecond intervals `[assignedAt, endedAt)`, scoped to member/game. A locked member/game state row owns the single current pointer and command version. Each assignment ID also identifies its progress period; its revision changes only when authoritative contributions are replaced. Admission creates legacy onboarding evidence, full assignments and current pointers on the same transaction as the identity. Deactivation closes current intervals at its actual command time, clears pointers and revokes access together. Reinstatement never restores them: administrators explicitly assign new qualifications and roles.

Migration `0010_qualifications` preserves `0000`–`0009` SQL and all original `qualification_initial_assignments` rows. Only active legacy memberships whose `identity_epoch` is still its initial value of 1 receive full history/current pointers, preserving exact onboarding IDs and timestamps. Published identity commands monotonically increment that epoch on both departure and reinstatement; therefore current active status alone cannot establish continuity. A higher epoch can also reflect another identity operation, so it is conservatively ambiguous. Inactive and higher-epoch legacy rows retain their original evidence without an inferred full interval/current pointer. They require explicit new assignments or supported historical resolution; neither a departure date nor uninterrupted membership is fabricated.

Telemetry uses a verified actual start to select the assignment and effective immutable rule version, independently of receipt/end/processing time. A mid-trip change or late upload cannot select today's rules. Unknown start, a history gap, a pre-initial start or missing rule publication returns explicit unresolved status. Undated manual evidence keeps its gameplay timestamps unknown; the coordinator supplies the actual confirmation instant for qualification/progress attribution. A repeat preserves that instant, rather than using the current query clock.

`historical_resolution` requires supported explicit `assignedAt` and exclusive `endedAt`, a reason, a past nonempty interval and no overlap. It inserts a new interval without changing old accepted attribution. A later adjudication must explicitly replace the contribution/version to apply newly supported history. Normal initial/reinstatement/correction commands reject historical date fields. Administrative corrections cannot advance an existing current level; ordinary advancement uses promotion confirmation.

## Authoritative contribution seam

Trips owns `trip_contributions`: exactly one current row per canonical trip, with a monotonic contribution version and immutable replacement history. The internal caller-transaction seam `qualifications.replaceContributionsInTransaction` combines identity current locks, qualification lookup and trips-owned register primitives. It has no browser acceptance setter and takes no browser/source acceptance flag. VTC-029 must first commit the reviewed effective trip decision/current fact on the same transaction, then call this seam before commit. A pending correction retains the prior decision/fact/contribution until staff acts.

The register rechecks canonical owner/game, expected canonical version and current immutable fact under deterministic trip locks. Accepted valid canonical evidence receives credit only with resolved attribution and known positive actual distance; telemetry additionally requires supported whole-trip distance and complete recording. These positive-distance/completeness rules follow VTC-027 company acceptance, not a new company threshold. Manual recording completeness is deliberately unknown and is not a telemetry-completeness requirement; its screenshot/reviewer checks belong upstream. Planned/provider totals never substitute for actual distance. Accepted confirmed-event trips use the same seam without repeating ordinary rule eligibility or duplicating credit.

A batch replaces canonical and alias contributions together; aliases lose credit, and unmerge explicitly restores their reviewed independent version. Exact current-version replay is a no-op, conflicting reuse fails, and older contribution versions cannot regress state. Rejection/revocation, distance/fact changes, attribution changes and merge/unmerge recompute affected old/new periods. No increment-only async projection or first outbox subscription is needed. Progress reads synchronously sum the register, return a real `computedAt`, period revision and `projectionPending:false`.

## Promotion, roles and correction alerts

Lock order is company, sorted actor/target members, member/game state and assignments, sorted canonical trips, then contribution/decision state. Confirmation rechecks current session/epochs/capabilities, active target, expected state version/assignment, immediate next level and authoritative totals inside one transaction. One captured confirmation instant selects the immutable rule for eligibility and proof and timestamps the new assignment/proof; a scheduled rule crossing during execution cannot mix requirements from different instants. An immutable proof retains source/target periods, threshold rule version, both requirements, exact confirmation totals/revision, actor, time and reason. Individual source quantities/thresholds retain `DECIMAL(38,18)`; aggregate proof distance uses widened `DECIMAL(65,18)` so summation cannot overflow one-source precision. Arithmetic uses integer-scaled exact sums and canonical strings.

Passing Trainee in either game calls the identity-owned same-transaction role facade. It replaces only global Trainee with Driver, preserves Dispatcher/Deputy and the singleton Director pointer, and leaves the other game's assignment alone. Qualification, roles, proof, audit, safe outbox and idempotency result commit atomically. A failed event append rolls them all back. Whole-transaction retries use identity's existing bounded classified rollback policy; ambiguous COMMIT is never blindly retried.

After a contribution replacement, confirmed proofs for affected old/new periods are re-evaluated against their **recorded** requirements. The mutable private review state is separate from immutable confirmation proof. An invalidating transition emits one versioned `promotion.review_required` safe event; another replacement while still invalid does not repeat the alert. Restored requirements clear current review state, so a subsequent invalidating transition receives a new version. The assigned qualification is retained throughout: no automatic demotion occurs. Persistent state/outbox establish the administration alert seam; inbox/polling/UI delivery remains downstream.

## HTTP and privacy

The existing VTC-028 OpenAPI routes provide levels/rule history, rename/publication, own/admin assignment history, assignments, public/own/admin progress and promotion confirmation. The VTC-029 trip review assignment route remains unmounted. Commands use current authority, same-origin session-bound CSRF, strict JSON/closed body schemas, UUID idempotency and strong `If-Match` ETags. History/progress ETags represent the member/game command state, while progress `projectionVersion` is the assignment's contribution revision. Publication/rename ETags represent the level version. Replays retain original safe command results, and stale versions conflict.

Lists use default 25/max 100 bounded keyset SQL and signed cursors bound to user/session/access epoch, route/game/member/level and history state version. Levels order by ascending structural ID; rule versions by descending effective time/ID; assignment history by descending assigned time/ID. Other-member progress omits review flags/reason codes entirely. Own/admin progress includes only a stable private explanation code; no raw evidence, staff reason or source payload enters these DTOs. History exposes supported intervals, not private reasons.

## Migrations, checks and remaining gates

The single additive migration contains structural bootstrap and continuity-fenced onboarding backfill after schema/FK creation. Named constraints fit MySQL limits. The existing dedicated locked migration runner retains sticky partial-DDL/uncertain-receipt behavior; DDL is not transactional. Synthetic reset drops contribution children and promotion/state children before assignment/rule/level parents without disabling FKs. Upgrade tests preserve the exact ten-migration prefix/checksums, onboarding IDs/timestamps and inactive/returned-active evidence, including actual pre-upgrade departure/reinstatement commands. The normal persistence/recovery lanes cover empty apply/replay, lost receipts, partial DDL and restored baseline.

`test/integration/qualifications.test.ts` uses real MySQL for start/effective boundaries, unresolved/manual history, exact thresholds, replacement/merge/revoke/idempotency, role preservation, same/different-game promotion races, promotion/correction locking, stale/ordinary/deputy authority, lifecycle/rejoin, atomic failure and API filtering. `test/unit/qualifications.test.ts` covers closed safe events, keyset binding and fail-closed config. Existing built-app smoke remains part of the isolated full suite; no mock qualification UI is introduced. Exact final-candidate verification/review/Required CI are reported in the delivery PR. Source code and prepared grants do not establish live migration, activation, notification delivery, production values or deployed acceptance.

## VTC-026 preparation and replacement

[Reconciliation](reconciliation.md) calls the owning `prepareInTransaction` facade before mutating canonical rows. It locks company/current members and qualification assignments in established order. Apply/reverse then calls `replaceContributionsInTransaction` with current locked facts/group membership, captured authoritative manual confirmation and new monotonic contribution versions. Alias credits disappear atomically; restored independent credits recompute historical periods and promotion reviews without automatic demotion.

VTC-029 consumes historical lookup and synchronous replacement through the [decision coordinator](trip-decisions.md). Staff-supported telemetry time preserves explicit `staff_resolution` attribution; first manual acceptance captures a stable confirmation instant. Current rule/assignment support participates in reviewed command guards; corrections keep promotion-proof alerts without automatic demotion.

## Member and staff workspace

The first section shows the selected game's current assignment, exact accepted count/distance, both promotion requirements and effective restrictions. Global roles grant permissions separately from game qualifications. Unset thresholds remain unset, Driver I is terminal, and reduced historical progress retains the assigned qualification with a review warning. The game filter is shareable in the URL. Assignment history shows supported half-open intervals; rule history shows immutable version/publication/effective times. Neither view claims to be a full audit feed or exposes private staff rationale or actor identities.

Director/Deputy controls provide a named, paged member selector, including former-member labels and full IDs for duplicate nicknames on the visible page. The selected member's full ID is also shown below. `GET /api/v1/admin/qualification-members` requires current `qualifications.manage`, selects explicit identity-owned public fields, and batches additive roles plus the singleton Director pointer. Exact ascending-ID keysets use default 25/max 100 and limit+1 lookahead. The query and role batch are bounded to 101; they do not pass 101 IDs to the existing 100-ID facade. Signed cursors bind route, user, session and access epoch. Generic `/members` and `/admin/members` remain unmounted.

Editors use the three registered typed restrictions and existing canonical catalog selectors. An omitted restriction differs from an enabled empty allowlist, and unknown sample facts differ from zero or non-hazardous cargo. Mass/distance inputs preserve strings and enforce `DECIMAL(38,18)` source precision; count inputs enforce the existing signed-integer persistence bound. Numeric launch values are never supplied by the workspace. Current restrictions are loaded from `level.ruleVersionId`, including when a newer future version exists.

Staff evaluate a hypothetical sample before explicitly confirming publication. `POST /api/v1/admin/qualification-rule-previews` is closed, JSON-only, CSRF protected, admitted before parsing under the existing rate limits, and limited to 64 KiB. It accepts game, registered rules, optional exact mass, up to 32 trailer facts/completeness and explicit ADR known/non-hazardous/unknown facts. It accepts no owner, source payload, company acceptance or confirmed-event context. Shared semantic validation checks duplicate types, bounded unique allowlists and exact mass precision; the VTC-027 engine supplies pass/fail/unknown with failure taking precedence over unknown. The response maps only registered rule types and allowlisted stable explanation codes. Preview writes no assignment, rule, contribution, audit, outbox or command receipt. It checks hypothetical qualification only; publication separately checks canonical game/kind references.

Any draft/sample change invalidates its preview. Immediate publication omits `effectiveAt`; a scheduled UTC input is calendar-validated and converted to canonical UTC milliseconds. Server preconditions reject past/duplicate effective times and obsolete level versions. Inputs survive recoverable validation, rate, conflict and unavailable responses; an uncertain identical command retains its original request, ETag and idempotency key across background refresh. A separate previous-action check remains available when a committed promotion changes eligibility before its response arrives. Success is shown only after a validated server response. Private queries include session/access scope, target, game and resource; game/target/access changes unmount stale commands and cancel obsolete reads.

Initial, reinstatement and administrative correction omit dates. Supported historical resolution requires an explicit past nonempty `[start,end)` interval and cannot overlap history. Ordinary correction cannot bypass next-level promotion. Confirmation uses the history/progress command ETag, never the contribution `projectionVersion`. Successful promotion refreshes affected queries and the session so Trainee completion updates the global membership role while preserving additive roles and the other game. Default-off activation and all hosted/launch gates above remain unchanged.

`test/unit/qualification-workspace.test.ts` covers exact boundaries, UTC calendar validation, unknown/non-hazardous facts and safe generated response parsing. Contract tests close preview authority/diagnostic fields and collection bounds. Real MySQL qualification tests cover authorized named pagination, 101-row lookahead, batched query count, representative indexed EXPLAIN, duplicate/former names, cursor privacy and mutation-free preview admission. Controlled browser journeys cover RU/EN layout, editor precision, stale preview, focus restoration, uncertain-key replay, conflict input preservation and unavailable/unset/review states. The separate real browser journey uses the built API, MySQL and owning manual/adjudication facades for accepted contributions; it edits/previews/publishes rules, selects a named target, assigns ETS2 and confirms promotion, then reads history and preserved ATS/additive roles. Qualification success responses are not mocked in that journey; authenticated captures are disabled. Actual run results and exact-candidate independent verification remain delivery evidence, not claims made by the presence of tests.
