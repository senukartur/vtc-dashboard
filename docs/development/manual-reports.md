# Manual reports and private evidence (VTC-025)

The [reviewed browser contract](../contracts/dashboard/manual-reports.md), [OpenAPI](../contracts/dashboard/openapi.json) and [CONCEPT.MD](../../CONCEPT.MD#manual-report-review-and-resubmission) govern this implementation. VTC-025 preserves drafts, original submissions, immutable revisions, correction requests and private screenshots. It does not implement VTC-029 acceptance, contribution recalculation or VTC-030 forms. A submission receipt creates review work, never qualification or statistics credit. No gameplay date is inferred from receipt or decision time.

## Activation and configuration

Manual reports are disabled by default. Activation requires explicit migration, identity, catalogs and trips, plus a separate random 32-byte hexadecimal `MANUAL_REPORTS_KEY`. The key signs scoped cursors and fingerprints; never reuse identity/mail/catalog/trips/telemetry keys. Configure `MANUAL_MAX_FILES_PER_REPORT` (1–100), positive `MANUAL_POLICY_REVISION` and `MANUAL_ORPHAN_GRACE_MS` (one minute through thirty days). These bounds are technical API/worker protections, not approved company qualification limits.

Uploads additionally require `MANUAL_EVIDENCE_ROOT`, `MANUAL_MAX_FILE_BYTES` (1–64 MiB), `MANUAL_MAX_PIXELS` (1–16 million) and `MANUAL_UPLOAD_TIMEOUT_MS` (100–120000). All are operator settings with no inferred production values. Without storage configuration, drafts/read discovery remain available and upload policy is disabled with null limits and an empty allowlist. Capacity, backup space and actual one-year retention must be demonstrated before activation.

The upload allowance starts after authenticated request admission, before waiting for the first multipart part, and remains active through byte consumption and image decoding. Expiry aborts the upload and closes its connection, including an unfinished first part header. This route-local body deadline does not configure global HTTP header or connection timeouts; database operations retain their existing settlement and recovery rules.

The root must already exist, be absolute, private, owned by the application user and outside served assets. On Linux require mode 0700, no symlink ancestors and a stable root inode. The application does not create/chmod a live operator path. A dedicated persistent mount at the established `/app/private-evidence` location is physically separate from the image release, despite the container pathname beneath `/app`. The production Dockerfile prepares mode 0700 for a fresh volume. Existing volumes require an explicit operator permission check; replacing an image does not chmod them. Existing backup/restore sentinels and mount names are preserved. No hosted configuration, volume, grants or files are changed by a source merge.

## Storage and validation

The replaceable private port uses generated `(evidence ID, generation)` identities and fixed `.staging`/`.blob` names. Original filenames are display-only. Exclusive no-follow staging, complete byte bounds, cancellation/deadlines, SHA-256, file sync, exclusive hard-link finalization and Linux directory sync precede readiness. There is no filesystem I/O under database row locks. Existing immutable generations are never overwritten or reused. Reads use no-follow/nonblocking descriptors and `fstat`, including FIFO/directory rejection. A writable application/operator trust boundary is required: this is not a sandbox against a malicious same-user process replacing directories.

The exact API dependency is sharp 0.35.5. JPEG/PNG filesystem loaders are explicitly allowlisted. Each child validates metadata and fully decodes every pixel to a bounded discarded raw stream; metadata/magic alone does not establish readiness. Original bytes remain unchanged. Warning/truncation errors, extra pages/channels, excess pixels, unsupported formats and MIME mismatch fail closed. The child receives no application environment or private credentials. Byte/pixel bounds, one native thread, disabled cache, a child wall deadline and a process-wide admission limit of two active decoders bound work. Admission rejects immediately; it never creates an unbounded waiting queue. Two is an implementation resource bound, not a member upload quota. Multiply it by the actual number of API/jobs processes when sizing deployment. The V8 heap bound is not an OS native-memory sandbox; deployment process/cgroup capacity still needs measurement.

JPEG/PNG parsing does not establish that the image depicts a completion screen or that reported values are true; staff review owns that determination. Windows checks are supplemental. Node does not support this adapter's directory-sync operation on Windows, so Windows tests do not prove power-loss durability. Linux sync/restart evidence does not establish host storage hardware guarantees.

sharp's JavaScript package is Apache-2.0. Native optional packages and bundled libvips libraries carry their own licenses, including LGPL components; the bundle is not uniformly Apache licensed. Production packaging must retain installed licenses/notices and shared libraries. See the [sharp installation](https://sharp.pixelplumbing.com/install/), [security guidance](https://sharp.pixelplumbing.com/security/) and [tagged native third-party notices](https://github.com/lovell/sharp-libvips/blob/v1.3.4/THIRD-PARTY-NOTICES.md). A binary deployment must preserve corresponding notices and license/source/replacement obligations. The deployment rehearsal invokes `manual-codec-smoke.mjs` in distinct production containers for write/read/remove phases on the persistent mount, checking full PNG/JPEG decode, original checksums/bytes, uid/root mode and installed Apache license/native license mapping/shared libraries after `pnpm deploy --prod --legacy`. This is separate from root dependency installation. Actual results belong to the candidate evidence; source preparation alone is not a passing rehearsal. Inspection of native package 1.3.4 found its complete upstream 29-library license mapping and later-version clause, but no full native license/copyright text bundle. The additional [offline original-text bundle](../../third_party/sharp-libvips-1.3.4/README.md) retains 803 original references as 343 unchanged SHA-256 blobs with source/version associations, full license bodies and explicit scope limits. Its verifier checks every byte and substantive license sections without network access in normal unit tests and inside the production image. The production smoke also compares installed native versions and all 29 mapping rows; libnsgif is vendored within one of the 28 versioned native entries. This is concrete content/provenance coverage, not a legal completeness attestation, exact production SBOM or bit-reproducible native rebuild claim. Source/build and custom replacement references are retained with the bundle.

## Transactions and immutable history

Current identity authorization precedes owner commands. The database company/member locks, actor/route/target key, keyed normalized fingerprint, report/draft versions, canonical trip/source writes, references, audit and safe outbox events share one transaction. Command records keep safe result identities and versions (legacy ordinary replies additionally retain their safe summary/reason-code snapshot); immutable draft snapshots and report revisions reconstruct ordinary replies. Unknown COMMIT is not automatically retried: clients reuse the same key to resolve durable state. Changed validated input returns an idempotency conflict. Optional event/comment absence normalizes to null only at submission.

Drafts have no trip/source/contribution. Submission validates all present canonical pins or preserves explicit unresolved diagnostics, then requires owner-ready evidence. Resolved retired values can be retained unchanged from prior history; new retired selections are rejected. Unresolved labels do not become catalog aliases. Exact quantities reject range/precision loss, including zero handling, without rounding. A caller cannot submit another owner, acceptance, qualification, attendance or timestamps through a closed DTO.

Report identity is permanent. Pending/rejected resubmission appends an immutable numbered revision on the same canonical trip and source identity. The narrow trips-owned supersession primitive validates the previous current manual message and expected canonical version; it never overwrites accepted facts. A telemetry target requires current owner/game/version and an actual telemetry source. Telemetry facts/times and conflicts remain preserved for review. The production composition's evidence callback verifies that a matching owned report/revision exists and its original fields/evidence match before an alternate source caller can store a new manual revision.

Legacy `ManualInput`/`ManualRevision` shapes remain intact. The separate optional-write DTO accepts omitted event/comment. Persisted revision format determines legacy versus extended readback through every route; a later client or catalog revision cannot reinterpret history. Trip history and report history return both formats. The batched owning projection supplies private manual data only after trips has authorized the owner/current reviewer; accepted company readers receive a summary.

Accepted author edits are rejected. A correction request records its immutable reason, base trip/revision and status history, holds evidence/review, and preserves the effective accepted result. Its ID is not a proposal ID. VTC-029 calls the transaction-scoped decision-retention seam after applying its own terminal trip state. The seam rechecks current staff authority, non-author, exact current revision and monotonic decision time; it records retention metadata only. There is no VTC-025 decision endpoint or contribution calculator.

## Upload and deletion recovery

Upload identity and processing lease are durable before a long stream. Concurrent attempts cannot take an unexpired lease. Actual decoded bytes/metadata determine the final fingerprint; exact ready retries return the same evidence identity, while changed bytes/name/type conflict. Rejected/missing interrupted attempts can retry under a fresh generation without permanently stranding the key. Recovery claims expired processing metadata, inspects/fully decodes any finalized immutable file outside locks, then commits ready or rejected under the same generation/token. It handles finalized-file/DB-not-ready and processing/file-missing states. Obsolete-generation cleanup requires its recorded intent, technical grace and metadata revalidation. Every initial/replay/retry candidate has a relational generation intent committed before filesystem I/O. Two indexed pages of at most twenty-five due generation intents rotate persisted `next_check_at`, even across separate cron processes. Bounded staging/blob presence checks run outside locks; metadata/current generation/lease is revalidated before a durable `manual.generation-delete` job. Current processing, ready and deleting generations remain protected. Failed/missing/completed jobs receive a new safe attempt without changing immutable generation identity. Missing observations and completed cleanup retain scheduled checks forever, so late filesystem completion is discovered by a fresh worker. Arbitrary unregistered files, including UUID-shaped names, are operator inspection only and never auto-deleted. No directory enumeration or recursive deletion is used.

Screenshot eligibility examines every historical report/revision reference. Missing decisions, pending/reopened review, correction holds, or a latest decision younger than one UTC calendar year protect the object. February 29 conservatively advances to March 1; unsupported year overflow never expires. Shared evidence uses the most protective reference. More than one hundred trips are acquired with current shared locks in globally sorted batches before the evidence lock, without a business reuse limit. Shared locks block concurrent decision writes while requiring only SELECT on trip state; existing exclusive trip command locks are unchanged. Changed discovery causes release/retry rather than late earlier-order locks. Draft-reference holds use a separate technical grace clock.

Eligibility reserves irreversible `ready -> deleting`, an immutable generation and a safe durable deletion job atomically. New attach/resubmit/reopen encountering the reservation returns retryable 503 `EVIDENCE_TRANSITION` and `Retry-After`; it never acknowledges active review depending on disappearing bytes. The worker deletes only that generation outside locks and marks expired under a fenced local completion. Repeated deletion of missing bytes is safe, including crash after unlink. Exhausted/missing/previously completed deletion jobs are reconciled through new safe effect attempts for the same tombstone; generic external mail ambiguity rules are unchanged. Disabled worker configuration remains visibly pending.

Expired metadata/checksum, original fields, references, reasons and structured history survive. Authorized expired content returns 410. A completed expiry does not promise resurrection; a new submission needs ready evidence. Private binary reads recheck current ownership/reviewer linkage and generation after opening, close on cancellation, and use no-store/nosniff/safe attachment headers. Unattached uploads remain owner-only.

## Migration and rollback boundary

Apply only through the locked migration runner, with API/jobs writers drained throughout migration 0011. MySQL DDL implicitly commits; no wrapping DML transaction makes this migration atomic. The SQL creates twelve manual tables and adds per-field catalog pin columns/FKs while preserving legacy global-pin FKs. Each field replaces its old check and adds its strict pin FK in one ALTER; this does not authorize concurrent writers. A failed statement leaves sticky `applying` history. Use the [persistence recovery runbook](persistence.md#partial-ddl-recovery-runbook), a consistent database/evidence backup or independently reviewed forward repair; never stamp/replay a partially applied migration blindly.

Published 0000–0010 SQL/snapshots and journal prefix remain unchanged. No explicit UPDATE backfill rewrites legacy facts/evidence. Old writes that supply only a global pin remain valid after the forward migration; the new reader falls back to that global pin. Known per-field identities require either a valid global pin or their own matching immutable scoped pin, with strict null/cross-pin checks. Trailer pins retain their own scoped catalog FK. An additive carrier defaults to adapter version 1 for old omitted-column writes and is bound to the parent fact version by a restrictive FK. A stored generated legacy pin enforces the original parent/global equality for version 1, so null or a forged version cannot bypass it; version 2 has an explicitly null global pin and uses its own scoped pin. Existing logical fact/evidence values remain unchanged. Same-report current-revision and report-trip reference FKs protect history/retention discovery. Their intentional FK cycle requires the fixture's named pointer-FK teardown before fixed-table reset; global `FOREIGN_KEY_CHECKS` is never disabled.

**Forward schema compatibility is not full old-reader compatibility.** Extended manual writes store adapter version 2. The old reader rejects that version and cannot reconstruct mixed pins from a global pin. Rollback to an old image is safe only before format-2 writes are enabled; after such writes, keep a compatible reader or perform an explicitly reviewed restore/forward repair. Drain writers and verify actual data before any rollback. Source merge does not activate format 2 on a hosted service.

## Prepared grants and remaining gates

Runtime generation intents need SELECT/INSERT and UPDATE limited to lease/time columns; workers need SELECT/INSERT/UPDATE for durable generation recovery. Runtime manual tables need SELECT/INSERT/UPDATE on evidence, reports, drafts and gates; SELECT/INSERT on revisions plus the narrow source-record completion UPDATE; SELECT/INSERT on command receipts, draft snapshots, references and correction history/requests; draft reference replacement additionally needs DELETE. Trips/source normalization requires its owning table writes and catalog SELECTs. Audit append needs INSERT; outbox append needs INSERT and current duplicate-read SELECT. Immutable command/source-message receipts use current shared reads after their existing actor/source-trip gates; their runtime grants remain SELECT/INSERT. Enqueue requires durable job INSERT/SELECT. Workers need the existing queue/receipt/lease grants plus manual evidence SELECT/UPDATE, reference/gate/trip reads and current locking-read privileges. Schema/migration privileges remain separate. The [concrete prepared additive matrix](../../deploy/development/manual-grants.prepared.json) is exercised by `manual-grants-smoke.mjs` in the deployment rehearsal: real draft/upload/submission/private review reads under runtime grants, then a distinct restricted worker reserves eligible ready evidence and deletes/expires its tombstone. The worker explicitly proves that exclusive FOR UPDATE reads on read-only domain tables are denied while FOR SHARE succeeds. Revision UPDATE is limited to `source_record_id`; immutable fields/reference/fact mutations are denied. This is the manual-chain matrix, not catalog administration or telemetry credential activation. The rehearsal applies it only to its synthetic accounts and revokes it afterward. Existing control-package update and hosted activation remain pending; the existing hosted activation matrix does not yet activate catalogs/trips/telemetry/manual reports and must not be treated as sufficient.

Required evidence remains exact-candidate independent verification/review, real MySQL permission/concurrency/idempotency and migration/recovery lanes, real Linux persistent-file fault/restart tests, protected built-server HTTP and production native decode/packaging. Production capacity, final volume permissions/grants, backups/restore and activation remain VTC-039/041/042. VTC-026/028/029/030 retain reconciliation, qualifications, actual decisions/recalculation and UI integration ownership.


The normal integration lane also uses a built `dist/app.js` listening socket for authenticated chunked multipart limits, interrupted socket/retry, binary bytes and current private access. It is distinct from handler-level `inject` tests. Frozen old facts/table-model fixtures prove legacy operations against forward MySQL schema; they do not represent a full old production-image launch.

For local diagnosis, `node deploy/development/test.mjs --manual-only` uses the same guarded production codec/grants proof and fresh synthetic allocation while explicitly leaving baseline acceptance and remaining regression stages NOT RUN. The default no-argument command and required CI still execute the full rehearsal. A focused pass never replaces the final full rehearsal.

Report/revision/history lists use descending timestamp/ID keysets. Equal timestamps use immutable ID order; revision numbers retain their within-report sequence. Equal-time pagination is covered without assuming a random UUID identifies a later submission.

Current integration preserves VTC-028 qualification/contribution storage. The contribution reader reconstructs format-2 scoped catalog pins through the same fact repository; manual gameplay times stay unknown and only an explicit actual confirmation instant supplies manual attribution. Submission does not populate contributions or grant credit. The common integration schema lifecycle and 60000 ms outer setup/teardown allowance come from the published VTC-028 baseline; runtime/query/transaction and negative-test deadlines are unchanged.
