# Catalog administration and selectors

VTC-020 adds `/account/catalogs` inside the authenticated member shell. Current `company.read` permits published search and history. Current `qualifications.manage` permits import, review, explicit mapping and publication, matching the [catalog API](catalogs.md). Catalog facts remain separate from qualification rules; this screen does not edit limits or infer launch configuration.

The existing Yukon Union dark surfaces, Onest typography, blue actions, visible focus and 44-pixel controls support a repeated staff job: inspect a maintainer-prepared update and publish the exact reviewed candidate. The first viewport contains game, current published revision and search. Review shows build, dated inventory, comparison revision, provenance, changes, coverage and publication gates. Native search/select fields and the existing Radix dialog supply keyboard and focus behavior. Responsive verification targets 390×844, 768×1024 and 1280×800 with RU/EN expansion.

## Published values

`apps/web/src/shared/catalog-selectors/` exports `CatalogSelector` and `{entityId, revisionId}` selection types. A consumer supplies game, published revision, kind, optional canonical region, selected value and change callback. Search text never creates data. Localized prefix search is debounced/cancellable and uses bounded cursor pages. The selected historical entity loads independently of active pages. Requested/rendered locale, English fallback and retirement remain explicit. Locale changes retain IDs. Incompatible game/kind/region/revision displays the retained historical value and an empty active selection. Consumers must validate compatible context before submitting a new form; filter changes must not silently submit the retained historical value.

Revision discovery returns the current pointer first, then historical publications. Optional `regionId` on `GET /catalogs/entities` filters the canonical region before pagination without changing unfiltered behavior. Foreign-game, absent or incompatible regions produce no matches. Signed cursors bind region, search, locale, revision and actor/session scope; changed filters start fresh pages. This does not establish production completeness or trusted aliases.

Queries use existing user/session-generation scope, private-cache metadata, no-store same-origin credentialed transport and runtime schemas typed against generated DTOs. Confirmed session loss clears private queries through the account boundary. Permission errors refresh current capabilities and hide failed query data. Privileged mutations are never optimistic.

Publication refreshes mutable candidate/review state before current-publication discovery. Pinned immutable entity pages are retained; a changed current revision creates fresh selector query keys. This replaces a nine-query invalidation burst observed in the synthetic publication/retirement journey against the API's five-slot fail-fast pool. The operation and publication pointer refresh on return; candidate review has an explicit refresh action and server ETag checks. This is scoped request-scheduling evidence, not a universal throughput guarantee or a production pool change.

## Import and review

Upload reads current policy and accepts one `application/json` file with browser-generated multipart framing. It displays returned artifact UUID, SHA-256 and byte length. Import is a separate command; its durable receipt is not publication. Validated operation/candidate UUIDs in the URL support authorized reload recovery. File contents and review reasons never enter browser storage or query mutation history. Operation polling pauses hidden/offline, stops terminally and refreshes on return. Failed, expired, unavailable and uncertain states offer safe recovery.

Child pages bind `reviewVersion`. Changes show allowlisted before/after facts and retirement. Coverage lists returned pack states, contributions, reasons and public provenance. Translations show returned English/Russian label changes, English completeness and the explicit Russian fallback policy. The API has no complete draft search/list, full translation queue or label editor; maintainers correct, review and reimport a new exact artifact.

Mapping requires an explicit returned candidate UUID, preserved provider/map/source context and reason. Missing source/map/candidates direct maintainers to correct and reimport. Draft labels appear only when actually returned in diffs; otherwise canonical IDs are shown. Real mapping edits invalidate exact-artifact source review. An approved hash cannot authorize edited data; synthetic test mode is not production approval.

Publication confirmation identifies game, build, candidate/version and separate pointer version. It requires candidate ETag plus `expectedPublicationVersion`, a reason, complete coverage/English/source review and no unresolved mappings. Only server success confirms publication. Conflict or missing-precondition responses close confirmation, invalidate review and require explicit refresh/new confirmation. Pending commands are locked; unchanged uncertain retries retain their logical key until explicit reset or confirmed result. Server retention is configurable and not exposed as a browser guarantee: after a long interruption, inspect operation/candidate/current publication before starting a fresh action.
