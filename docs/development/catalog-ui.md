# Catalog administration and selectors

`/account/catalogs` is inside the authenticated member shell. Current `company.read` reads the lists; `qualifications.manage` adds, edits, hides, restores and imports. The page has the ETS2/ATS `SegmentedControl` named "Game", seven tabs (DLCs, regions, cities, companies, depots, cargo, trailers), one search field and source/region filters; the choices live in the URL so a link restores them. The [catalogs model](catalogs.md) covers rows, codes and import.

## Layout

The desktop and tablet table shows the name, the Russian name on regions, cities, cargo and trailers, code, source, list-specific columns, and row actions for staff. Long names and codes wrap inside their own cell and never run under a neighbouring column; the date and actions stay on one line. It supports keyboard scrolling when the columns exceed the available width. Below 760px, cards put row actions behind a 40px button that opens a sheet. Staff add and import actions stay in the header on wide screens and move to a bottom bar on a phone. The trailers tab keeps the name "Trailers"; its form hint says the code is the telemetry body type and that a coupling counts as its first trailer's type.

Rows with no Russian name show the English fallback badge in Russian. DLCs, companies and depots use only the canonical name: no Russian column, form field, import column, fallback badge or Untranslated chip. Hidden rows show a badge and leave the default view. Without `company.read` the page renders only its heading and a notice and sends no catalog request. Without `qualifications.manage` every action is absent and no write route is called.

## Maintenance filters and row metadata

The **Hidden only**, **Untranslated** (translatable lists only) and company-only **No logo** chips use the selected game's summary counts for the current list. Missing counts have a localized unavailable label, and an available zero remains visible. Search and relation filters narrow the rows and the pager total. Changing an effective filter, game, tab or locale restarts pagination.

One maintenance mode is active at a time. The chips write `hidden=only`, `untranslated=true` or `logo=missing` to the URL and list request. The existing **Show hidden** checkbox still uses `hidden=true` in the URL and `includeHidden=true` on the wire. When a shared link contains more than one mode, the page keeps Hidden only, then No logo on Companies, then Untranslated, then Show hidden, in that order. Leaving Companies clears No logo, and `untranslated=true` is dropped on a tab without the chip. Selecting the pressed chip again restores the default view.

Tables and phone cards show the row's own `updatedAt`, formatted using the viewer's saved display timezone and locale, with the UTC value in the time element. Company rows also show the server's `depotCount`, including zero. An unavailable timestamp or depot count appears as a dash with a localized accessible label. Successful catalog commands refresh both lists and summary counters.

## Selectors

`apps/web/src/shared/catalog-selectors/` exports `CatalogSelector` and the runtime DTOs. A consumer passes game, kind (`city`, `cargo`, `trailer`, `company`), an optional region and the selected ID. The selector is one ARIA editable combobox with list autocomplete: typing searches through the server after a short debounce, reads only start when the field is opened, and a last row loads the next page inside the list. Rows that are hidden or from another game leave the list; a saved row in that state stays readable with its label, a mark and a note, and a consumer can pass the optional `extraRow` to add a fixed last list row (the four manual report fields use it for "Not listed / unresolved"; other consumers do not show it). A row that is still being fetched or has not settled after a search cannot be chosen. Locale changes labels only, never selected IDs.

For a city with a canonical name, the options, the chosen value and its title show that name in both languages with no English-fallback mark; search still runs over every name and the code. Trip, review, driver, dashboard and report-target surfaces keep the translated label and add the canonical name as muted secondary text only when it differs, ignoring case. Cargo and trailer rows are unchanged.

`DepotSelector` is the shared company picker for a city (used by the manual report's origin and destination company fields). It follows the same combobox contract over `GET /catalogs/depots?cityId=`: each option shows the company name on the left and its code on the right, so same-name companies stay distinct; typing searches the name and the code on the server; the chosen value reads `name · code`. Without a city the field is disabled. The consumer confirms the chosen company with an exact `companyId` read and clears it, with a notice, when the city no longer offers it.

Keyboard contract: arrows open and move (wrapping), Enter chooses the active row and never submits an enclosing form (IME composition is respected), and Escape closes the list and restores the previous value. Tab and clicking outside close and restore, except that fully erased text clears the value. Inside a dialog, Escape closes an open list first; `shared/ui/dialog.tsx` keeps the dialog open until the list is closed.

Queries use the session's private no-store scope and generated DTO runtime schemas. A failed read shows an alert and a Refresh row in the list. A selection whose row cannot be read keeps its ID and says so.

## Companies, depots and logos

The Companies tab uses the same table and phone cards, with the logo before the name. The edit form carries a Logo section: the current logo (or the placeholder), Upload or Replace, and Remove. The Depots tab lists Company (logo, name and company code), City and Source; the code is shown because one game brand is often several companies, one per facility type, so two depots of a city can share a name. The phone card's actions label and the depot edit form name the code too. Its filters for company and city use the shared company and city selectors and live in the URL. Staff add a depot with the same selectors and an optional source; an existing depot can only change its source or be hidden. A duplicate pair keeps the form open with an error.

A logo is shown on a fixed 128 by 32 plate with a light neutral background, since the artwork is made for unknown backgrounds and the page is dark. The image has an empty `alt` because the company name is always beside it. When a company has no logo, or the image fails to load, a neutral drawn mark (not a game asset) takes its place; the UI never requests an image for a company whose `logo` is null and never shows a broken image. On a phone the plate sits above the name inside the card and the page does not scroll sideways. The image URL carries the logo `version`, so a replacement shows at once. Logos load through one shared queue (`logo-loader.ts`) once a plate nears the viewport: at most three requests in flight, because the API's small database pool answers a burst with 503; a 503, a 429 or a network error is retried after `Retry-After` or a short backoff (capped at 10 seconds, up to four tries), one logo shown in several rows is fetched once, and a queued request nobody waits for any more never starts. The limit is per browser tab. The plate stays empty while its logo loads, and a logo already loaded in the tab is reused for its version without a new request, like the browser cache.

On the Companies tab staff also get **Upload logos** (**Logos** in the phone bar): pick or drop many `<company code>.png` files for the selected game, read the dry run (counts, then per-file results naming unknown codes and invalid files), and apply. The logical command keeps one idempotency key while the files and token are unchanged. Depots reuse the import dialog with their own columns and templates.

## Import flow

The dialog offers CSV and JSON templates per list and shows the exact columns, then checks a file through the preview route. Counts and per-line results appear with errors and changed fields; errors disable apply, and a truncated line list is called out. Apply sends the same file with the preview token in `If-Match`; the logical command keeps one idempotency key while the file and token are unchanged, so an uncertain retry cannot double-apply. A stale token asks the staff member to check the file again.

## Evidence and boundaries

Unit tests cover the logo URL, depot and logo schemas, selector compatibility, combobox row order and key movement, fallback rules, URL filter parsing, template parity with the server's columns and RU/EN string parity. Browser tests cover RU/EN layout at desktop and phone widths, add/edit/hide/restore, import dry-run/apply, permissions, pending, error and empty states, and the combobox keyboard, search and paging behavior. Run the pinned Docker launcher from [testing.md](testing.md). The maintenance browser cases cover shared URLs, reset after filter changes, optional counts, command refresh, keyboard operation and row metadata at 390, 768 and 1280 pixels in both languages. The real API cases use isolated MySQL fixtures to compare the displayed filters, counters, depot counts and timestamps with the API responses and saved timezone. Exact outcomes per candidate SHA belong in the pull request.
