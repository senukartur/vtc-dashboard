# Versioned catalogs

VTC-019 implements catalog preparation, private normalized artifacts, durable staged imports, reviewed publication, historical reads and a server-side resolver. [CONCEPT.MD](../../CONCEPT.MD) and the [VTC-019 backlog](../planning/mvp-trello-backlog.md#vtc-019) retain the all-official-DLC target. Synthetic tests establish machinery only. They do not establish complete ETS2/ATS launch datasets, usable reviewed English labels, permitted metadata distribution or downstream trip/qualification acceptance.

## Preparation and trust

Extraction is a separate authorized operator action. These tools never launch a game, modify an installation, acquire a DLC or extract assets/localization themselves. Work only on separately extracted trees in ignored private storage. Do not commit prepared artifacts, source definitions, private paths or actual game labels before permitted-use/attribution review.

`node scripts/catalogs/prepare.mjs <private-source-manifest.json> <new-private-output.json>` expands explicitly ordered layers, registries and includes. The manifest is `{ "layers": [{ "root": "<private-extracted-root>", "packId": "base", "registries": ["def/city.sii"], "overlay": false }] }`. Roots are private inputs and excluded from the source fingerprint. The fingerprint binds ordered pack/registry/overlay choices and file hashes in expansion order. Preparation preserves relative origins and overridden-unit evidence in its private output. Missing/cyclic/duplicate includes, duplicate units in a layer, unapproved overlays, symlinks, escaping paths, invalid UTF-8, unknown fields and unsupported syntax fail closed. Limits bound bytes/files/depth/tokens. Supported reviewed fields include city/country/cargo/trailer facts, city arrays and the selected country/license-plate definitions; this is not a general game-definition interpreter.

`node --import tsx scripts/catalogs/build.ts <private-source-manifest.json> <private-reviewed-input.json> <new-private-artifact.json>` binds every proposed entity to one exact active source unit and its complete observed values. The reviewed input contains `artifact` (the schema below without `sourceManifestSha256`), explicit `ignoredUnits: [{unitType,unitId,reasonCode}]` for unrelated definitions, and `bindings`, each with `kind`, `mapNamespace`, `key`, `unitType`, `unitId`, `sourceFacts`. Every active city/country/cargo/trailer-definition unit must have a matching typed binding; recognized catalog units cannot be ignored. Other source units require a binding or an explicit reviewed non-contribution reason. Unit facts must match the parsed active unit and owning pack; a cargo unit-mass mismatch fails. Review supplies canonical source keys, readable labels, separately reviewed aliases, external mappings and typed references. Localized source tokens never automatically become English names or aliases. The command prints only normalized byte length/hash/counts. Neither command overwrites an existing output.

The source build/manifest and artifact hash are evidence bindings, not license verification. Operator-owned trusted configuration must independently record the exact artifact SHA-256, game/build, complete expected pack IDs, inventory date, public provenance/attribution/use basis and reviewed English labels. Uploaded strings or approval flags cannot establish trust. Production publication requires an exact match to that reviewed allowlist. There is no network license checker and no automatically trusted game installation.

## Normalized artifact v1

The strict executable schema is [artifact.ts](../../apps/api/src/modules/catalogs/artifact.ts). Every object rejects additional properties, including private source paths and invented approval fields. All fields are explicit; unknown facts are `null`:

- Root: `schemaVersion: 1`, `importerVersion: "vtc-catalogs/1"`, `synthetic`, `game`, `gameBuild`, `releaseInventoryAsOf`, `sourceManifestSha256`, `packs`, `provenance`, `entities`, `mappingIssues`.
- Each pack: `packId`, readable `title`, `state` (`validated`, `missing`, `failed`, `non_contributing`), `contributionKinds`, public `provenance`, safe `reasonCodes`. Include base and every official pack in the independently reviewed launch inventory, even a missing/failed/non-contributing pack. Validated contribution kinds require actual entity contributions. Non-contributing packs cannot claim contribution kinds.
- Each entity: exact `key`, `kind`, `mapNamespace`, `packId`, explicit `retired`, `labels: {en,ru}`, `aliases: [{locale,label,regionKey}]`, `mappings: [{provider,sourceId}]`, `regionKey`, `cargoUnitMassKg`, `adrCategoryKey`, `trailerBodyTypeKey`, `trailerChainTypeKey`. References must resolve within this artifact/game/map to the correct kind. Cargo mass is a canonical exact nonnegative DECIMAL(38,18) string; it is **unit mass**, never shipment mass. No coordinates are accepted or interpreted as latitude/longitude.
- Each mapping issue: `provider`, `kind`, `mapNamespace`, nullable `sourceId`/`sourceLocale`, safe `reasonCode`, exact `candidateKeys`. Unknown/ambiguous provider evidence stays explicit; a candidate list is not a trusted mapping. Public projections expose canonical candidate IDs, never source files.
- Public provenance: server-format UUID `referenceId`, HTTPS public URL without credentials/query/fragment, attribution/use-basis text and UTC `observedAt`. No paths or source payloads belong in these fields.

Exact source keys/provider/map namespaces support at most 128 Unicode scalar characters/512 UTF-8 bytes; invalid surrogate sequences fail. Identities preserve case, accents, composed/decomposed Unicode and trailing bytes. Alias normalization is separate: NFC, collapsed whitespace and Unicode lowercase with accents retained. Alias normalized keys are limited to 512 UTF-8 bytes and validated before retention. Display labels must be readable, trimmed and free of source localization tokens; a missing Russian label visibly falls back to reviewed English without creating an alias. Missing English blocks publication. Display search uses localized prefix matching under the display collation and never defines identity.

Canonical UUIDs are minted by the server from the stable exact `(game,kind,map,key)` identity. Revision facts get separate UUIDs. Source keys must remain stable across preparation; changing a source key is not a rename. A subsequent artifact must explicitly retain every prior published entity, including retired entries. Omission fails import rather than retiring or deleting historical facts.

## Configuration and private storage

Catalog routes/imports are disabled by default. Opt-in requires identity and explicit `CATALOGS_ENABLED=true`, `CATALOGS_CURSOR_KEY` (independent random 32-byte hex key), `CATALOGS_MAX_FILE_BYTES`, `CATALOGS_ARTIFACT_TTL_MS`, and positive `CATALOGS_POLICY_REVISION`. Technical policy permits 1–8,388,608 file bytes and 60,000–604,800,000 milliseconds retention. These are technical storage/worker bounds, not business catalog limits. `CATALOGS_EVIDENCE_FILE` optionally names a private UTF-8 JSON array of trusted evidence records; absence leaves real source review pending. Deploy/API/worker must receive consistent reviewed configuration. No runtime settings, grants or hosted scheduler are applied by source merge.

Each trusted evidence record has `artifactSha256`, `game`, `gameBuild`, `releaseInventoryAsOf`, `expectedPacks`, `provenance`, `englishLabelsReviewed: true`. The exact hash binds all artifact facts, aliases, pack states and mappings. The operator must independently verify the full release inventory and evidence, not copy asserted claims from an upload. Keep this file, cursor key and paths private. `CATALOGS_SYNTHETIC=true` is accepted only outside production and enables only artifacts explicitly marked synthetic. Synthetic mode never authorizes real artifacts. Real artifacts without an allowlist entry can be inspected but cannot publish.

This module deliberately stores only bounded normalized JSON bytes in private MySQL MEDIUMTEXT. This scoped choice avoids filesystem attachment/orphan races; it does not replace the general private evidence Blob port for report screenshots/assets. Strict schema validation precedes storage; the exact uploaded UTF-8 bytes, byte length and SHA-256 are retained unchanged. The 8 MiB cap is below MEDIUMTEXT byte capacity. There is no artifact download/path endpoint. Creator/current-capability checks protect metadata/import/operation readback. Expiry clears private bytes while retaining safe metadata, published immutable facts and structured history.

`@fastify/multipart` 10.1.4 explicitly supports Fastify 5 in its [pinned source](https://github.com/fastify/fastify-multipart/blob/v10.1.4/index.js). Upload allows one `file` part with MIME `application/json`; fields/extra parts are rejected. File bytes, fields, part count, field size/name, header pairs and stream truncation are checked. An additional stream counter caps total multipart bytes at file policy plus 16 KiB framing. The general Fastify JSON body limit is not used as a multipart aggregate guarantee. JSON commands keep the existing 64 KiB body bound.

## Durable import and recovery

Upload returns 202 only after private artifact metadata/bytes commit. Import returns 202 only after the actor-bound idempotency result, operation and first durable `catalog.import` job commit together. Identical concurrent commands replay one durable result; a changed payload under the same actor/scope/key conflicts. Results expire under the configured artifact retention window; clients must not treat keys as permanent deduplication identities.

Each job carries only operation/artifact IDs, exact hash, phase and offset. Optional queue `prepare` reads/parses the bounded immutable artifact outside effect locks under the queue's abort/deadline budget. Local commit keeps the existing job-token/expiry fence and effect receipt, rechecks the stored artifact/hash/expiry and expected durable cursor, commits one bounded batch plus its next job and advances the cursor atomically. Stages are identities, facts, links/diffs, mapping issues and finalization. Fact batches contain at most 100 entities; issue batches contain at most 10 issues. This preserves the normal platform lease/pass budgets and supports work spanning multiple minute passes.

Staging revisions have `complete=false`; every HTTP and resolver read rejects them. The operation exposes no result until finalization checks historical retention and commits coverage plus `complete=true`. No import stage moves publication. A crash before commit retries the same batch after lease recovery; a committed batch and its next job survive restart together. Unknown COMMIT outcome stops the pass without blind replay; durable cursor/receipts reconcile the next run. Expired bytes, parse/hash errors, omitted history or exhausted jobs produce safe failure status. Queue failure details/raw SQL/source payloads do not enter operation DTOs.

Enabled jobs perform bounded cleanup. It terminalizes expired/failed incomplete operations, marks their revisions rejected, prunes inaccessible partial child/fact rows in restrictive FK order, expires command results and clears expired private bytes. Canonical identity records and safe operation/revision history remain. Never reset a live database or delete shared volumes to repair an import. After an uncertain commit, inspect safe operation/job/cursor state and use the normal lease recovery path. A failed import cannot replace the published pointer. Disabled workers pause `catalog.import`; compatible worker configuration is required before resuming. Disabling an already active feature must retain a compatible cleanup worker or run the reviewed keyless cleanup deliberately.

## Review, publication and reads

The existing [browser contract](../contracts/dashboard/openapi.json) owns routes/DTOs. Member reads require current `company.read`; import/review/mapping/publication require current `qualifications.manage`. Origin/CSRF/no-store/idempotency follow identity. Operations additionally require the creator and their current initiating capability. Director/deputy capability checks are refreshed inside the same transaction before catalog locks.

Candidate ETag is `"vN"`; review/diff/coverage/issue requests bind the exact candidate version. Signed keyset cursors also bind actor/session/access epoch, revision, lane and filters. Fixed-revision entity/diff/issue lists use descending IDs (all share revision creation time); coverage explicitly uses ascending exact pack ID. Command fingerprints use a purpose-separated HMAC under the private catalog key. Mapping diffs encode provider/source pairs as separately indexed bounded strings and alias-set changes as normalized SHA-256 summaries with an explicit reason code; full aliases remain part of independent exact-artifact review. Mapping edits are draft-only and bump candidate/review version; old review cursors conflict. Unresolved mapping issues block publication. Adding an exact mapping resolves matching source issues and updates the normalized source-mapping diff; it never guesses from display names.

For real artifacts, a mapping edit invalidates source review. The current wire contract intentionally has no approval-upload shortcut: prepare the edited normalized artifact, obtain independent operator review of its new exact hash and reimport it. The previous edited draft stays pending; it cannot claim approval of unchanged source bytes covers newly edited mappings. Synthetic tests can exercise direct draft mapping/publication in the isolated synthetic mode. This distinction is visible in revision/review source-review fields.

Publication requires both candidate `If-Match` and separate `expectedPublicationVersion` (initial empty pointer version 1), current comparison revision, complete pack/English/source review and no unresolved mapping issues. It locks authority, pointer and candidate, then commits the new pointer, published revision/version, safe audit and `catalog.published` outbox event on one UnitOfWork connection. The staff publication call approves the exact candidate/version. A changed pointer or candidate conflicts; imports must be prepared again against the new comparison. Previously published facts/mappings stay immutable and readable, including retired facts. New selection lists exclude retired entries. Concurrent readers explicitly pin one complete revision. The revision list returns the current pointer revision first, then historical publications by `(createdAt,id)` descending; its cursors bind the pointer version and conflict after publication. Import creation time does not determine the current revision.

The internal resolver reads published pinned local facts. It first matches exact provider/source ID in supplied game/kind/map/region context; an unknown supplied ID remains unknown even if a label matches. Name-only resolution uses reviewed normalized aliases, optionally locale/region scoped. Missing context with multiple matches returns ambiguity. It returns canonical entity and fact-revision UUIDs, never a guessed ID or translated label. Owning authenticated use cases must authorize their caller before invoking this server facade.
