# Member administration and connection settings

[VTC-038](https://trello.com/c/deMxSaXu) composes the existing Identity, Admissions, Qualifications, Messaging, External Identities and Telemetry owners into the RU/EN account workspace. Product policy remains in [CONCEPT.MD](../CONCEPT.MD); the [browser contract](../contracts/dashboard/README.md) owns wire shapes. Implementation and local synthetic verification do not activate hosting, real mail, provider accounts or production launch configuration.

## Workspace and current authority

`/account/admin/applications` provides submitted/approved/rejected URL tabs, bounded review/detail/history, decisions and invitation inspection. Since VTC-063 it is a compact queue table with the detail beside it on wide screens, below it on medium widths, and in its place below 700px (with Back to list), whose detail shows the applicant facts, email history, the decision with a required rejection reason and the invitation block; mockup elements without API support (tab counts, search, sorting, relative times, reviewer names) are left out. `/account/admin/members` provides active/former member lists, additive role editing, deactivation, explicit reinstatement and verified Steam replacement. Since VTC-064 it is a compact table (Active/Former tabs, a role filter, a debounced nickname search kept in URL parameters, role badges, ETS2/ATS levels, last accepted trip and status) with the panel beside it on wide screens, below it on medium widths and in its place below 700px (with Back to list). The panel shows the header facts, per-game qualifications, a confirmed Trainee/Driver membership switch, additional roles, Steam replacement and deactivation or restore; each command asks for its required reason inside the confirmation. A null last accepted trip reads as "None recorded"/"No accepted trips recorded", never as a member who has not driven, because it is also null when Trips is not configured. For the serving Director the membership, roles and deactivation are shown unavailable with the protection explanation (Steam replacement stays available), and the leadership transfer link appears only for the Director. Mockup elements without API support or approval (tab counts, a qualification filter, an accepted-trips count, member-since and deactivation dates, avatars, removing Trainee/Driver membership from the panel) are left out. `/account/admin/settings` provides company reporting timezone, a link to the existing qualification workspace, actual source capabilities, safe audit references and serving-director transfer. Since VTC-065 it is a compact page: a reporting-readiness banner, a Reporting card (validated IANA timezone and the qualification setup row), trip sources with implemented/planned and enabled/disabled/unavailable badges, and the audit log, with the director-only transfer panel beside them on wide screens and below them otherwise; a deputy gets no panel. It has no company name, public page or Discord settings, and mockup elements without API support (preset timezone list with offsets, per-game readiness, audit names, a masked email, an in-place done step) are left out. `/account/connections` provides personal telemetry credentials and Steam/TruckersMP status as the Connections section of account settings. The role-grouped sidebar, responsive navigation dialog and user menu link these routes according to current capabilities, and the pages no longer repeat section links; direct API authorization remains authoritative.

The administration coordinator mounts only when Identity composition is configured. Existing feature flags remain disabled by default. There is no new activation switch, migration, inferred production timezone, numeric qualification limit, provider credential form or adapter installation. `GET /me/connection-capabilities` reports whether personal telemetry and external-identity services are enabled in this runtime. `GET /admin/source-capabilities` reports implemented and enabled states separately for telemetry/manual and explicitly deferred company-owned Trucky/VTCBase adapters. No synthetic `SourceConnection` record or deferred write endpoint is created. Drivers own personal telemetry credentials; planned company webhook setup for Trucky/VTCBase is reserved for the Director and deputies and remains unavailable until those adapters are supported.

New admin routes have persistent bounded admission before body parsing, current active session/capability checks, closed generated schemas and `no-store`. Writes require exact Origin and session-bound CSRF; commands use UUID idempotency keys and member/company `If-Match` as defined in OpenAPI. Existing Admissions, Messaging and External Identities admission remains separately owned, avoiding a broad double-charging admin hook. Anonymous, ordinary, deputy and director requests remain distinct. Every private read rechecks current authority in its query transaction.

Member pages use ascending-ID keysets, default 25 and maximum 100. `GET /admin/reinstatement-options` separately returns the eight structural game/code/name/ID choices through Qualifications under `members.manage`, including when qualification rule HTTP is disabled. Safe Identity fields and current additive roles are selected explicitly; current per-game assignments come from the Qualifications facade on the same transaction. Detail responses include authoritative `version`/ETag. The lookahead is trimmed before the at-most-100-ID qualification projection. Selected-member detail and reinstatement confirmation resolve human level names and localized progression stages through the same safe structural option read; canonical IDs remain secondary references and command identities. A missing or unavailable label is explicit and cannot silently become an invented level name. Administration cursors use an HMAC domain distinct from qualification cursors and bind route, actor, session, access epoch, effective status and limit. Admissions status filtering is performed in SQL and its cursor binds status/history and limit. Unknown member IDs return a safe 404 to authorized staff.

`GET /admin/members` also accepts optional `role` (Trainee, Driver, Dispatcher, Deputy Director, or Director, which matches only the serving-director pointer) and `search` (a case-insensitive nickname substring; surrounding whitespace is trimmed, a blank term is 422, and `%`, `_` and `\` match literally). Both filters run in SQL before the keyset limit and are bound into the signed cursor with status, so a cursor reused with a changed filter is 409; cursors issued before VTC-064A are refused once. Each list and detail row carries `lastAcceptedTripAt`: the latest `reporting_at` of the member's accepted canonical (non-alias) trips, or null without a dated accepted trip. It is the only activity signal; there is no online or last-seen indicator. One grouped Trips read covers the at-most-100 selected IDs after the qualification projection, as a plain consistent read without trip locks (company → sorted members → qualifications → trips). It can use the existing owner-prefixed trip indexes but still visits each selected member's trip rows; no migration or index is added, and a covering index is a follow-up if measured plans need it. The read runs only when the Trips module is configured, because only then does the runtime database role hold SELECT on `trips`; otherwise the field is always null and member administration needs no Trips grant.

## Lifecycle and protected operations

`PUT /admin/members/{memberId}/roles` replaces the explicit selected additive role set. It does not change per-game qualifications. Director is never assignable through this command. Generic role changes and deactivation/reinstatement of the serving Director remain forbidden under current company/member locks. The members panel sends only Dispatcher/Deputy Director changes through this command, keeping the member's current Trainee/Driver roles as the server reported them; its confirmation states that saving roles signs the member out and revokes personal telemetry credentials. The membership switch and the additional-roles save are offered one at a time: unsaved changes in one disable the other.

Since VTC-064A, `PUT /admin/members/{memberId}/membership` sets the membership directly to exactly one of Trainee or Driver with a required reason, member `If-Match` and UUID idempotency key. It replaces only that membership role: a member holding both or neither is normalized to the requested one, and other additive roles, per-game qualifications and assignment periods, sessions, telemetry credentials and access/credential/identity epochs are unchanged, like trainee promotion (capabilities are recomputed from current roles on every request). It appends `membership.changed` audit and access events and increments the member version. Requesting the membership the member already holds alone is a 409 `STATE_CONFLICT`; inactive targets are 409. The generic roles command keeps its existing session/credential invalidation. Every protected change to the serving Director (roles, membership, deactivation, reinstatement) returns 403 for both Director and Deputy actors without any state change, under the same company/member locks.

Deactivation closes current qualification periods, invalidates current access/credential epochs, removes sessions, consumes private challenges and clears access roles. Reinstatement uses the same user identity and requires explicit replacement roles plus one or two unique per-game assignments of purpose `reinstatement`. Each level must belong to the specified game; historical dates, duplicate games, a current interval, wrong purpose, active targets and stale member versions fail. One server instant starts the new periods. Identity, roles, qualification state/history, invalidation, audit, outbox and idempotent result share the caller transaction and company → sorted members → qualification lock order. The shared qualification assignment writer also serves ordinary qualification commands. Old intervals and source/trip ownership remain intact.

Telemetry's configured invalidation port eagerly revokes old credentials in the same transaction while enabled. Disabled telemetry retains its existing no-token-table-access boundary; monotonic captured-epoch/link checks prevent revival when re-enabled. Reinstatement never restores old sessions, challenges or credentials.

Steam replacement is a separate proof-specific operation, not an email/login repair. Staff can inspect cached target status through `GET /admin/members/{memberId}/identity` without impersonating that member or refreshing the provider per row. Only a fresh verified proof for the target's current epoch is offered for application; the server rechecks all proof/session/link/epoch fences. The existing VTC-018 rule allowing a deputy to apply the Director's own verified Steam proof is preserved. It cannot change the Director's protected email/password channel or leadership pointer.

Leadership transfer remains serving-Director-only. The current verified email receives the existing one-time ten-minute code bound to an active successor. `POST /admin/leadership/transfers` accepts only `challengeId` and `code`. Identity resolves the stored successor and then rechecks current authority, locks, successor and exact challenge in the atomic command. The panel enters the code inline, then confirms in a dialog. Its expiry, remaining attempts and resend countdowns come only from the state read and a 429 `Retry-After`, are plain text rather than live regions, and the code step resumes from the state read after a reload. A refused code closes the dialog, keeps the typed value and re-reads the state; a code the server no longer reports is explained and cannot be submitted. Change successor clears the code and returns to the successor choice, and a new request is needed. After a confirmed transfer the session changes, the page shows Access restricted, and a dismissible notice names the successor; only the public nickname passes through router state, which is then cleared from history so a reload or Back does not repeat it. Requests are limited to one code per 60 seconds and five per 60 minutes; a refused request returns 429 with the exact `Retry-After`. `GET /admin/leadership/challenge` (serving Director only) restores the pending code's ID, successor, expiry and remaining attempts plus `resendAvailableAt` after reload, without exposing the code or email. The old Director retains Driver and any other additive roles and qualifications. An invalid challenge's 401 triggers a separate self-session check rather than automatically declaring logout.

## Invitation and personal secrets

An invitation link can be shown/copied independently of mail. Reissue creates a new generation and invalidates the old link; it is distinct from requesting email for the same generation or retrying a known failed delivery. The invitation block names these actions Copy link, Send to email, Retry email and Reissue link. Copy, Send and Retry are shown only while the link is active and unexpired; expired, used and replaced links are explained instead, and Reissue is offered for active or expired links.

Bodyless `POST /admin/invitations/{invitationId}/email-deliveries` requests the first email for a currently valid, unconsumed, still-current generation with no existing delivery. It requires invitation `If-Match`, UUID key and current `applications.manage`. The owner decrypts and checks the link privately and enqueues mail on the same transaction. The token, generation and expiry are preserved; delivery/version metadata only is returned. Disabled mail or enqueue failure rolls back. Existing delivery inspection and resend use Messaging ownership, ETag and its supported failed/retryable rules; accepted, simulated, ambiguous, suppressed and obsolete deliveries cannot be generically reopened. Provider acceptance and local simulation never claim inbox delivery.

Personal telemetry issuance requires current `trips.submit_own` and verified Steam. The secret is displayed once in a dismissible dialog and is absent after reload. Listing returns safe labels, creation/last-use/revocation times only. A validated successful response completes the command before subsequent list refreshes: the command deadline is cleared and its one-show value is returned for immediate local presentation. A delayed or failed refresh remains a separate read state and cannot turn that confirmed issuance into an uncertain command or trigger another issuance. A lost issuance response retries the same frozen request/key. `SECRET_ALREADY_ISSUED` returns the caller-owned credential reference and offers revoke-then-explicit-create recovery; it never silently mints another token. Revocation remains the Telemetry owner command.

Private query keys include identity, session generation, identity epoch, current capabilities and effective URL/resource state, with private metadata for clearing. A resource-level read denial reconciles the current session before authority-scoped query keys or session-loss clearing cancel obsolete reads; unchanged authority does not blanket-cancel unrelated permitted requests. Connections gates personal-token requests and every associated read/list/pager state by `trips.submit_own`; identity verification remains independently available to non-driving staff. Connection-local sensitive state also remounts on authority-scope changes. Transport forwards cancellation and fences obsolete selection/session reads. Confirmed writes start separate refreshes that cancel affected reads and clear obsolete data; refresh failure never reclassifies the confirmed command. Uncertain writes retain the original target, body, key and ETag; recoverable forms retain input. Links, secrets, codes and provider authorization URLs stay in feature-local memory, outside query/mutation caches, storage, diagnostic output and application URLs. Dismissal, navigation, logout and session change clear their feature lifetime. Sensitive dialogs receive the initiating control captured before the asynchronous request, and restore it on Escape or explicit dismissal while it remains connected, visible and enabled. Successful telemetry issuance retains the non-secret label so its initiating control remains available.

## Reporting settings and audit

Company settings use the existing `identity_company.reporting_timezone` column, validated IANA timezone, company version/idempotency and same-transaction configuration audit. Personal display timezone changes formatting only. `launchReady` here describes reporting setup: timezone plus actual currently effective qualification rules and nonterminal promotion thresholds through the owning facade. Timezone alone never makes it true; this is not full deployment or launch acceptance.

`GET /admin/audit` authorizes current `members.manage` in the query transaction. Both views include the singleton company's rows and rows without a company reference, ordered by `(occurredAt,id)` descending. Omitting `view` keeps the legacy fields and cursor scope. `view=stage3` adds object type, current actor nickname, object name and allowlisted before/after details. An optional `action` matches exactly before pagination. Stage 3 cursors bind the actor, session, access epoch, view, action and limit. The response omits the optional total.

Stage 3 resolves actor and user object nicknames for active and former members after trimming the page lookahead. The matching company object uses its public name. Admissions resolves application and invitation nicknames only when enabled and currently authorized by `applications.manage`. Unavailable labels and missing, unsupported or malformed snapshots return null while preserving the audit row. Identity and Admissions capture new snapshots with the domain write in the same transaction. The details exclude private reasons, contacts, messages, SQL, provider payloads and credentials. Existing indexes remain unchanged; synthetic representative `EXPLAIN` evidence is diagnostic, not a production sizing claim. VTC-039 remains the broader audit/observability card.

The settings page shows audit times in the member's display timezone with an explicit label. The named audit scroll region is keyboard-focusable so native Left/Right keys can expose columns on narrow layouts; it keeps a visible focus outline.
