# Durable jobs and transactional events

[VTC-021](https://trello.com/c/O04FbGzZ) supplies the MySQL queue, immutable safe outbox, local effect receipts, named runner lease and bounded CLI. It uses the existing [UnitOfWork](persistence.md), MySQL 8.4.11/InnoDB and UTC `DATETIME(3)`. Migration `0003_windy_jackal` follows the three published migrations without changing their bytes. Startup never migrates or seeds.

## Producers and subscriptions

`createOutbox(unit).append(tx, envelope)` accepts the closed schema-v1 families in the [event registry](../contracts/dashboard/events.md). The original `member.access_changed` envelope contains application event/correlation/nullable causation UUIDs, member aggregate ID and positive membership version, an explicit occurrence instant, and exactly `{userId, accessEpoch, identityEpoch}`. Aggregate ID equals user ID. UUID shape, positive signed-INT versions, millisecond precision and plain data descriptors are validated. The finite fields impose a small technical bound; arbitrary/private extensions are rejected. These bounds do not set company business policy.

`identityAccessEvents(unit)` implements the existing identity port on the membership/audit transaction. Server composition installs this adapter. The port has no caller correlation seam, so correlation is event ID and causation is null. Current membership remains synchronously authoritative. Identity delivery remains absent/fail-closed; this card implements no private mail.

Concurrent duplicate inserts lock/read the durable identity and compare a SHA-256 fingerprint of the normalized envelope. Changed input reusing an ID fails the transaction; no outbox UPDATE/DELETE is used. MySQL rolls back the expected duplicate statement only. The enclosing producer owns whole-transaction transient retry after rollback.

No access-event consumer is installed. Ordinary jobs retains events visibly as `unboundEvents`, without acknowledging a fictional effect. Future reviewed subscriptions explicitly register type/kind/consumer and a safe reference validator. Anti-join catch-up returns at most 25 events per subscription and uses `(event_id,consumer)` uniqueness with no timestamp-only watermark, preserving late commits. That result limit does not bound scanning retained history. Before installing the first subscription, its owner must capture representative routing EXPLAIN and scan/work measurements including already-routed history, and assess bounded scanning while preserving late-commit correctness. Other contract event types remain planned. Events, jobs and receipts retain identity evidence indefinitely; archival/deletion needs a separate replay-preserving design.

## Queue and effects

`createQueue(unit, handlers, subscriptions)` is an internal facade, not a public endpoint. Each code-reviewed versioned handler owns a closed reference validator; the technical JSON ceiling is 4096 UTF-8 bytes. Common rows never contain private mail, credentials, screenshots, raw source payloads or exceptions. Kind/consumer codes are exact binary ASCII up to 64 bytes, non-null effect keys up to 128 bytes. Enqueue requires an explicit due instant and attempt limit 1–5. Duplicate consumer/effect or event/consumer identities cannot overwrite input. Changed input conflicts. Chained enqueue shares the caller transaction.

Transitions are `ready -> running -> completed`, `running -> ready` for explicitly retryable local failure, or `running -> failed`. Separate indexed ready/expired selections use deterministic due/ID order and `FOR UPDATE SKIP LOCKED`. Every committed claim increments attempts and creates a random token. Expired final claims become exhausted. Terminalizing an expired row may end the current pass; inspection retains the remainder for later minute runs.

Local execution re-reads the authoritative job, checks token and database lease, reserves a unique consumer/effect receipt, applies the callback/chained writes, checks expiry again, and completes on the same transaction. Reclaim cannot enter the locked job. Stale tokens cannot apply effects, renew, retry or complete. Lease overrun rolls back receipt/effect/chaining. `receipt(consumer,effectKey)` returns only durable `{jobId}` for response-loss reconciliation. Future projections additionally own aggregate/contribution-version guards; receipt identity does not establish ordering correctness.

Local callbacks perform database work only through the supplied transaction, with no network effects. Deadlock/lockwait retries repeat the whole safe transaction at most three times with 10/20 ms backoff after UnitOfWork explicitly rolls back/discards the failed connection. Exhausted deadlock/lockwait retries and allowlisted pre-COMMIT driver transport/query timeout failures transition local work through the existing durable `retryable` backoff and claim-attempt limit; they never silently become successful effects or automatically replay a connection failure inside the same execution. Arbitrary SQL/handler failures remain terminal `handler_failed`. Unknown COMMIT and lost lease take precedence even with a transient-looking cause: end the pass without blindly replaying claim/callback/completion. Re-read durable job/receipt or preserve lease recovery state. Ordinary producer transaction/deadline policy is unchanged.

The external hook commits the claim before network I/O and supplies the durable consumer/effect key. At its current pre-fence it measures the authoritative remaining MySQL lease, subtracts monotonic elapsed time across the clock read and COMMIT receipt, and reserves six seconds for completion. The callback receives this shrinking budget and a composed cancellation signal; an exhausted budget prevents callback entry and uses the narrow ExternalNotStartedError retry classification. This also covers an already-aborted signal before callback entry; it does not establish safety after possible invocation. Adapters must use provider idempotency where available and own reviewed reconciliation. Callback/completion failures and expired external claims conservatively become terminal `external_ambiguity`, even when a crash might have preceded the call. There is no automatic ambiguity reopen/retry primitive. Provider acceptance followed by response loss therefore cannot blindly repeat an irreversible effect. VTC-014 adds the explicitly configured mail handler described below, with bounded requests and frozen provider keys. Other future adapters must bound/cooperate with cancellation and the 15-second job lease or supply reviewed renewal composition.

## Budgets and inspection

| Technical bound | Implementation |
| --- | --- |
| Schedule | One invocation each minute |
| Concurrency / pool | One handler; one shared five-slot UnitOfWork per worker |
| Normal pass | 40 seconds monotonic elapsed; stop claims on budget/signal |
| Process ceiling | Independent supervisor kills its owned child at 50 seconds; signals allow five-second drain |
| Worker client ceiling | 55-second Docker client budget, then remove the owned container and verify absence; the [full operations tick](../operations/development.md#durable-jobs-existing-installation-update-and-acceptance) additionally includes heartbeat, image inspection and bounded cleanup |
| Work/routing | At most 100 executions; 25 events per registered subscription per routing call |
| Job / runner lease | Database UTC 15 / 20 seconds; renew runner before each route/claim cycle |
| Attempts/backoff | At most 5 claims; retry delay 1/2/4/8 seconds within this bound, formula capped at 60 seconds |

The independent supervisor can terminate synchronous noncooperative callbacks and unresolved async/SQL work. SIGTERM/SIGINT stops claims and aborts cooperative work. Normal cleanup closes the pool; forced termination relies on MySQL rollback/disconnect and lease expiry. Never set the internal `VTC_JOBS_WORKER` marker in runtime configuration. Killing a Docker client alone does not stop its container or SQL; root operations verifies owned-container absence and keeps recovery fenced on cleanup failure.

Portable artifact commands are `node dist/jobs.js run` and `node dist/jobs.js inspect`; workspace `pnpm jobs` uses the built entry. Output includes fixed state/failure counts, oldest due time, retained/unbound events, bound consumer count and at most 25 failure IDs/kinds/versions/attempts. No raw references, native SQL errors or public failure API exist. Categories are `retryable`, `exhausted`, `missing_handler`, `invalid_input`, `external_ambiguity`, `handler_failed`. Missing handlers/unsupported versions never count as success.

Potential connections are readiness 5 + API UnitOfWork 5 + jobs UnitOfWork 5 + probe 1 + heartbeat 1 = 17 before administrators; development MySQL allows 24. Operations locking excludes migration/export/restore overlap. Arithmetic is not measured capacity. An accidental overlapping minute process is also fenced by the database runner token; direct queue consumers use independent job claims/receipts.

## Verification and synthetic acceptance

`jobs-acceptance` is a separate opt-in composition requiring `VTC_JOBS_ACCEPTANCE=synthetic-only`. Ordinary jobs never registers `acceptance.counter`. Its closed references contain only run UUID, sequence 1–1000 and stage 1/2. An independent unique fixture counter records effects. Stage 1 transactionally chains stage 2; sequence 2 deliberately retries once. `seed` creates ten identities idempotently, `run` uses the minute runner, `consume` exercises direct queue consumers, and `crash-claim`, `crash-effect`, `hang` expose controlled boundaries. Nothing sends network traffic or implements a trip/notification.

The real-MySQL integration lane covers production tables/APIs, atomicity, conflicting/concurrent identities, late commit routing, held-row skip, persisted leases/reclaim/stale fencing, exhaustion, rollback/chaining, receipt reconciliation, missing/unsupported handlers, real deadlock/lockwait rollback/exhaustion and pre-COMMIT connection loss, runner overlap/loss, external ambiguity and process crash/restart. Full-row claim EXPLAIN uses 900 synthetic rows: 800 completed, 80 future-ready, 5 due-ready, 10 running with future leases and 5 expired-running. It explicitly analyzes the owned fixture table, observes both unhinted production predicate/projection/order/limit/locking shapes and requires the respective ready/expired indexes. This selective mixed history fixture avoids inferring an access path from 150 all-ready rows or an empty expired set; it proves neither production plan stability nor host capacity. Persistence/recovery lanes cover empty/replay/published-prefix/sentinel upgrades, checksums and interrupted DDL. Existing protocol tests retain UnitOfWork COMMIT/half-open behavior; queue tests require unknown-outcome precedence without replay.

Run `pnpm check`, `pnpm build`, `pnpm test:local integration`, `pnpm test:local persistence`, `pnpm test:local recovery` and `node deploy/development/test.mjs`; final isolated verification runs the complete suite. Actual results and candidate SHA belong in delivery reports. [Hosted acceptance](../operations/development.md#durable-jobs-existing-installation-update-and-acceptance) requires separately authorized application of the reviewed package. Local rehearsal and the VTC-011 heartbeat do not prove minute scheduling, host capacity or domain jobs acceptance. Downstream concept scenarios remain their owning workflows' gates.

## VTC-014 mail handler

The normal CLI registers mail.deliver only when mail is explicitly configured; disabled composition excludes that kind from both ready and expired claims, retaining pending work. The generic queue still terminalizes missing handlers. Its common reference is exactly {deliveryId}; no outbox subscription is installed. Typed ExternalRetryError permits only an adapter-reviewed safe retry with a bounded delay (up to one day); ExternalRejectedError records a known terminal rejection as handler_failed. All other external exceptions keep external_ambiguity, while unknown COMMIT/lost-lease precedence is unchanged. Queue-owned retryRejected always uses a current locking read on the caller transaction and accepts only a failed known-rejection job or durably ready retryable job with matching registered handler/version/reference, remaining attempts, no lease and no effect receipt. Resend calls it regardless of the private mail outcome state. It retains the original job, payload, key, due time and attempt counters; running/ambiguous/exhausted/completed work cannot be reopened. Mail persists accepted receipts separately before queue completion. See [email](../operations/email.md) for provider retention, quota handling and recovery. Default disabled operation still retains unbound access events.
