# Canonical trips and source evidence

[VTC-022](https://trello.com/c/CI8ticl7) implements internal source adapters, immutable receipts and normalized fact revisions, a conservative canonical projection, and three approved browser read APIs. Apply the additive `0008` migration explicitly. Set `TRIPS_ENABLED=true` with identity enabled and a separate random 32-byte hexadecimal `TRIPS_CURSOR_KEY` to install reads. Startup never migrates, imports trips or accepts them. Catalogs may be disabled: source IDs then remain explicitly unmapped. The VTC-019 technical foundation is available; complete reviewed real catalogs and permitted-use evidence remain pending.

## Identities and transaction boundary

`createTrips(...).storeInTransaction(tx, provider, payload, context)` joins the caller's existing `UnitOfWork`. The trusted caller derives the local owner and connection context; source payloads cannot set company acceptance, qualifications or attendance. Own telemetry is registered as `ets2telemetry`, manual revisions as `manual`; unregistered providers fail closed. Future webhook adapters must implement the versioned `TripSourceAdapter` interface and pass their own reviewed contract/authentication gate before registration. No Trucky/VTCBase implementation exists.

The permanent source-trip key is `(provider, game, pluginSessionId, tripId)` for telemetry. Database UUID, token, binding and installation are provenance, never additional uniqueness scope. Manual identities use the immutable report UUID for session/trip keys and immutable revision UUID for event identity. Application IDs remain UUIDv4 `BINARY(36)`; frozen provider UUID-shaped keys retain their exact version-free shape as bytes. Revision strings preserve every safe positive provider integer, including values above signed INT; application aggregate versions are independently bounded.

The database enforces unique `(provider,eventId)` and `(sourceTripId,revision)`. Exact content comparison uses SHA-256 of RFC 8785 canonical JSON: UTF-16 property order, unchanged Unicode, preserved array order, no lone surrogates/nonfinite or unsafe integer numbers. Integer-looking property keys are serialized directly in sorted order. Identical retries reuse the same receipt. Reused event content or a second event reusing a revision conflicts without overwrite. Current active membership and trip-submit capability plus permanent ownership are checked before exposing any receipt, including after raw expiry. The packaged telemetry schema is an exact copy of the frozen [contract schema](../contracts/telemetry-v1.schema.json); an equality regression prevents drift. Its single-file Biome exclusion preserves canonical bytes rather than creating a second editable schema.

The identity facade locks current company/member state before source identity and canonical rows. Each command uses one connection for source, facts, projection/history and outbox. The outer caller uses the existing bounded transient transaction retry; `storeInTransaction` never starts a nested transaction. COMMIT uncertainty is not blindly retried. VTC-023 owns bearer tokens, installation/binding validation, transport limits, durable HTTP ACK and source endpoints. This internal source foundation is not an activated telemetry service.

New sources normally allocate a canonical trip. A reviewed higher-level coordinator may pass `context.canonical={tripId,expectedVersion}` to attach a new source identity to an explicitly chosen existing canonical. It must be the same owner and game and the locked version must match. An existing source cannot be retargeted through this seam. This trusted linkage preserves original source identities. VTC-026 now adds audited canonical groups and conservative candidate discovery; VTC-029 still owns acceptance. Source values replace a supported projection or remain conflicting evidence; they are never added together. The source envelope and trusted owner/target context are captured before asynchronous checks; normalized facts derive from that frozen JSON copy so caller mutation cannot disagree with the stored content hash.

## Facts, axes and revisions

`source_messages` retains immutable event identity, hash, revision, receipt time and delivery mode. `source_trips` retains permanent ownership/link and initial server connection context. `trip_facts` stores relational immutable outcome/completeness, source time/basis/verification, exact nullable quantities, coverage flags and pinned city/cargo/ADR entity and fact references. `trip_fact_trailers` stores bounded ordered known/unknown trailer references; its parent count detects missing history. Null represents an unknown normalized value; zero remains known. Composite restrictive FKs bind each catalog fact to the stored entity and revision, including each trailer's own scoped catalog pin. VTC-025 adds nullable per-field pins while retaining legacy global-pin FKs; see the [dual-format migration and rollback boundary](manual-reports.md#migration-and-rollback-boundary). The additive `catalog_fact_pin` unique key supports those constraints and is created before the new FKs in migration `0008`.

The fact repository reconstructs all normalized values and references from these relational columns and owning source identity joins. JSON retains field provenance, unknown/review reasons, money and selected raw extensions; a redundant immutable adapter snapshot is evidence only and cannot replace relational quantities, identities, times, axes or pins. Internal `sourceEvidenceInTransaction` exposes that reconstruction to reviewed coordinators. `trips` stores the current authoritative identity/projection/version; `trip_history` records projection changes. The current fact pointer is written only from the locked same-owner/game effective canonical group; reads validate membership while preserving each fact's original trip identity. Restrictive FKs retain owners, messages, trailer/fact history and pinned catalog revisions.

Four axes remain independent: game outcome (`open`, `delivered`, `cancelled`, `none`), company decision (`unassessed`, `pending_review`, `accepted`, `rejected`), recording completeness (`complete`, `partial`, `unknown`), and server connection context (`unknown`, `bound`, `disconnected`). No administration connection store is implemented. Fresh evidence is always `unassessed`, regardless of outcome/completeness or connection state. There is no accepted contribution, qualification progress or notification effect on receipt.

Out-of-order terminal snapshots, including revision 1, are stored immediately. Benign lower revisions remain history without regressing the projection, incrementing its version or emitting another lifecycle transition. Higher open refreshes are fact changes. Contradictory terminals, attempted reopen and supported fact/time changes retain explicit review reasons; conflicting obsolete terminals are also visible in private detail. Conflicts preserve the effective fact pointer. Accepted facts remain frozen and later source evidence sets correction pending for later staff resolution. This foundation records flags/reasons, not staff review work items or decisions.

Known zero differs from unavailable. Valid telemetry quantities outside the exact DECIMAL(38,18) normalization envelope become unknown with `quantity_out_of_range`; the original unsupported number is retained in selected structured provenance and the source receipt still commits. No value is rounded and the transport contract is not narrowed. Controlled manual decimal input rejects unsupported precision before storage. Canonical decimal strings preserve base units: metres, kilograms, litres and damage fractions. Planned, observed/measured segment, delivered and supported whole-trip actual distance are distinct. Whole-trip actual distance requires complete supported lifecycle/coverage evidence; an open/partial recording never turns a measured segment into the total. Different observed/delivered values carry a conflict reason without inventing a tolerance. Damage above 1 remains raw anomalous evidence and becomes unknown normalized fraction, never clamped. Raw monetary integer/type/currency and other mode/build/locale evidence remain in immutable source payloads; money is additionally retained with normalized facts. Cargo unit mass/count never manufacture actual shipment mass.

Actual times require supported matching event sequence/basis, observed lifecycle and no clock anomaly. Checkpoint, last-known, receipt, out-of-range or otherwise unsupported times never become actual start/completion. Millisecond UTC is preserved and receipt remains separate. Undated manual revisions have unknown actual times and no reporting date; confirmation/attribution belongs to later decisions. Normalization pins one complete published catalog revision for the transaction with an exact supported game-build match. It prefers the current matching publication, then the newest retained complete published revision for that same exact build; byte-sensitive comparison prevents case/Unicode collation from proving compatibility. Missing build or no matching published revision yields explicit unknown catalog facts while preserving the source message and provenance. No API version or label substitutes for a build, and current catalogs never silently supply historical ADR/trailer facts for an unsupported build. Exact scoped mappings establish identity; labels are not a fallback identity proof. Missing maps/catalogs, unknown/ambiguous mappings, ADR or trailer evidence remain explicit unknown facts. Later publication cannot rewrite stored facts or their display references.

The manual adapter accepts canonical selections, exact quantities and immutable evidence IDs from an already-authorized revision coordinator. It requires a caller-transaction `manualEvidence` validator and published same-game/kind selections. Its default composition has no evidence port, so manual writes fail closed. VTC-025 owns form/blob validation, screenshots, manual revision/comment history and browser commands. This card does not claim those implemented workflows.

## Read authorization and events

The unchanged approved wire contracts expose `GET /api/v1/trips`, `GET /api/v1/trips/{tripId}` and `GET /api/v1/me/trip-status-summary`. Queries recheck current session, membership, epochs and capabilities inside their query transaction. Company scope includes only accepted summaries; mine includes only the actor's trips; review requires current `trips.review`. Other members receive an accepted summary only; inaccessible detail returns 404. Owners and current review staff receive the private contract with actual review reasons and empty/null future workflow fields. No raw envelopes, source histories, screenshot references, money or private reasons leak through company summaries. `Cache-Control:no-store` applies and detail has a strong aggregate ETag.

Lists use descending createdAt/id keyset order, default 25/max 100. Signed cursors bind actor, session, access epoch, scope, game, decision and sort; current authority is checked on every page. Owner summaries and pinned labels use batched narrow owning facades. Decision counters partition personal trips, while active and correction-pending counts overlap. No analytics totals or fabricated future workflow data are returned.

The closed v1 producers are `source.snapshot_stored`, `trip.lifecycle_changed`, and `trip.facts_changed`. Their common data is exactly `{sourceRecordId,tripId,factRevisionId}`. Source aggregates use the immutable source record at application version 1; trip aggregates use the current canonical version. Source revision is not coerced into an event version. All commit atomically with their writes. Internal `eventContextInTransaction` returns retained delivery mode, receipt and supported occurrence facts for future freshness/backfill suppression after payload expiry. No consumer/subscription or routing scan change is installed; the existing first-subscription gate still applies. Events are retained/unbound and do not imply notification delivery.

## Retention and operational gates

Raw content lives separately in `source_payloads`. The default eligibility deadline is null, which never expires. There is no approved numeric raw TTL, production cleanup scheduler or automatic policy. An authorized internal coordinator must explicitly supply a reviewed policy reference, eligibility instant and hold using `retentionPolicyInTransaction`. `expirePayloadInTransaction` locks/rechecks the canonical row and payload, including current pending review, correction flag, review hold, explicit hold and deadline. Expiry at the eligible instant is allowed only if every guard passes. Reopened review and concurrent holds serialize against cleanup. Manual source payloads are outside this cleanup.

Expiry clears only raw content and records expiry time; permanent hash/receipt identity, ownership/link, normalized facts, source timestamps, money, selected structured provenance and history remain. Retained provenance includes source/binding/database identity, producer/context/mode, original lifecycle basis/sequences, mapping IDs, trailer evidence and quality; this is a reviewed whitelist, not another complete raw-envelope copy. Raw display labels and other unselected extensions are removed with raw content under that policy. Replays after expiry return the same receipt without creating another trip. Raw-only extensions/provenance can be removed only under that explicit future reviewed policy. The [one-year screenshot policy](../../CONCEPT.MD#screenshot-retention) remains unchanged: latest decision and renewed review govern VTC-025 evidence retention, independently of this raw-envelope seam.

Tests cover canonicalization, exact adapter schema/semantics, units/time/unknowns, current authorization and HTTP privacy, concurrency/replay/conflicts, explicit source linking, confirmed freeze, raw retention boundaries/holds, rollback, restrictive FKs, mixed-history EXPLAIN and the exact eight-migration upgrade prefix. These are synthetic local checks, not production dataset, real-game, hosted capacity, deployment or acceptance evidence. Integrated acceptance, analytics, notification consumers and hosted activation remain separate gates.

[VTC-023](telemetry.md) exposes the frozen bearer ingestion boundary and reuses `storeInTransaction` on the authenticated binding transaction. Its receipt ID is the immutable source-message ID; the facade returns persisted first-received time for new and exact duplicate messages even after raw payload expiry. Synchronous normalization/projection and the existing outbox commit before ACK. Acceptance, contributions, statistics and notifications remain separate.

Source commands read the revision guard and the complete current fact/trailer projection using current locking reads after locking the canonical pointer. This prevents a telemetry authentication snapshot opened before a peer commit from missing that newly committed projection under REPEATABLE-READ. Ordinary list/detail reads retain their consistent snapshot behavior.

## VTC-028 contribution register

Trips now owns one monotonic current contribution per canonical trip and immutable replacement history. [Qualifications](qualifications.md) coordinates historical attribution and old/new promotion proof checks through the caller-transaction facade. The register derives acceptance from locked canonical state and actual distance from the pinned current immutable fact; it never consumes a source/browser accepted flag or provider total. Aliases lose credit through a deterministic batch replacement. VTC-026 now drives audited merge/reversal replacement; adjudication remains VTC-029.

## VTC-026 canonical groups

[Reconciliation](reconciliation.md) adds Trips-owned flat aliases while preserving immutable original source/fact ownership. Effective membership governs reads, source arrival, private projection, retention and contribution validation. Aliases do not add counts. Current fact membership checks validate the selected fact against the complete same-owner/game group; they are not removed. Production source callbacks and Qualifications preparation share the caller transaction.

VTC-029 adds the [decision coordinator](trip-decisions.md), relational derived-fact provenance and a reversal-fencing adjudication marker. Source rows/messages remain immutable; effective derived facts still back the real contribution FK. Read the post-activation old-reader rollback boundary before deploying an older artifact.
