# VTC-016 public landing and membership application

The public company page is available in Russian at `/` and English at `/en`. The language control changes between those routes without storing form data. Company information, the required application fields, the review/invitation explanation and established public community links share one content source. No production totals, qualification thresholds, private contact details or legacy membership data are imported or prerendered; company totals appear only at runtime from the [VTC-052 public aggregate](analytics.md#public-company-statistics-vtc-052).

## Routes and initial HTML

The web build renders the shared public React content into deterministic RU/EN documents. Both contain meaningful content, language, title and description before JavaScript executes. The client adds the interactive application form and the live parts described below. With JavaScript disabled, the page explains how to enable submission and keeps public contact links usable.

Language-alternate (`hreflang`) annotations are deliberately omitted until a verified public deployment origin is available. Google requires fully qualified URLs for these optional annotations; relative `/` and `/en` annotations are invalid. The localized documents remain indexable with meaningful language, title and description metadata. No deployment hostname or canonical URL is inferred. See [Google's localized-version guidance](https://developers.google.com/search/docs/specialty/international/localized-versions).

Document generation requires exactly one language, robots, title and application-root marker in the built shell; a missing or duplicated marker fails the build. Function replacements preserve literal dollar sequences in generated content, and metadata text is escaped for its HTML context. A `finally` cleanup covers partial SSR builds, renderer import, rendering and file-write failures. Cleanup failure also fails the build; if both generation and cleanup fail, both errors are retained. Public community destinations remain those approved for this landing, with HTTPS used for the existing Steam group.

The built API selects an indexable public document only for exact, query-free `/` and `/en` URLs. Query-bearing public URLs, unknown routes, `/status`, foundation previews, account/invitation paths and the `/events` boundary and account entry points receive the noindex shell and `X-Robots-Tag: noindex, nofollow`. Static document filenames also receive that response header. Request/query values are never reflected into generated HTML. HTML and API responses remain `no-store`, except a successful anonymous [company statistics](analytics.md#public-company-statistics-vtc-052) response (`public, max-age=60`); fingerprinted JS/CSS and landing MP4/WebP media are immutable, including Range (206) responses. Reserved API/health/evidence/upload paths and missing assets retain 404 behavior. Vite development serves its ordinary shell; verify initial public HTML against the production build.

`/status` preserves the real cancellable readiness query, pending/error/503/retry semantics and authenticated MySQL baseline probe. `/foundation` and `/foundation/member` remain explicitly synthetic previews. `/events` honestly explains that public listings belong to VTC-035; `/login` opens the [VTC-017 account screens](account.md). These boundaries do not publish participant data or simulate account workflows.

## Live landing (VTC-050, R7d video design VTC-089)

The page follows the approved R7d design and is deliberately dark and self-contained: `landing.css` redeclares every shared token it uses for `.landing-shell` and the portalled menu, so a light theme (VTC-083) needs its own treatment. Order: header, video hero, convoys (`#convoys`), nine event formats (`#events`), cab view, about (`#about`), nine-rank ladder (`#ranks`), the three join steps with the form (`#apply`), the six community links (`#contacts`) and the footer. `LandingHeader`, `LandingContent` and `LandingFooter` are shared by the build-time renderer and the app; `AppLayout` uses them on `/` and `/en` instead of the ordinary public shell.

The prerendered RU/EN documents depend only on the locale and static content: the hero still, slogan, lead and links, every section's static copy, the no-script note and contacts. Everything time-dependent, fetched or media-related renders only in the client through `LandingContent` slots, so repeated builds are byte-identical and no `<video>`, MP4 URL, countdown, stats, pause control, form or convoy card is in the initial HTML. The countdown slot is always reserved, so the slogan never moves.

- **Header and menu.** Logo, five section links, sign in (or the workspace link for a session), language select, the existing notification bell and Apply. Section links move behind a menu button at 1050px and below; sign in and language follow at 760px. The menu is the existing Radix dialog styled as a top sheet: it traps focus, locks scrolling and starts on the first link; Esc, outside click and Close return focus to the button. A section link closes it, moves focus to the section (`tabIndex=-1`) and scrolls there; header, hero and menu section links do the same on plain clicks, also for the current hash. Without JavaScript (`@media (scripting: none)`) all links wrap in the header and the reserved menu space disappears.
- **Hero video.** A 16:9 full-width frame (300–940px tall) with a bottom fade. The prerendered `<picture>` shows the frame at 1 s (`hero-still-854` up to 760px, otherwise `hero-still-1280`, high fetch priority). After the window `load` event and an idle callback (1.5 s timeout), and only without reduced motion, the client mounts two stacked muted inline layers of `hero-854.mp4` (up to 760px) or `hero-1280.mp4`, chosen once per mount. Muting and `playsinline` are set before the source; playback starts at 1 s (`#t=1`). Layers stay transparent until the first `playing`, and the second layer downloads only then. `hero-loop.ts` crossfades to the other layer, restarted at 1 s, during the last 0.9 s of the clip and parks the old one after the fade; if the other layer cannot show a frame yet it restarts the current one instead of showing black. A media error or a rejected `play()` (for example Low Power Mode) removes the video and leaves the still; there is no retry. Playback pauses while the tab is hidden, the hero is off screen or the pause control is pressed. The site never plays sound and has no sound control.
- **Departure pill.** The earliest scheduled public convoy that has not started, linking to its event page. The visible text shows a minute-granular countdown (rounded up); the accessible name stays fixed as "next convoy: title, absolute start time" in the browser timezone, and there is no live region. One timer runs until the next minute change or the start; when the convoy starts, the shared list is refetched once per event and the pill moves on.
- **Convoy cards.** All returned public events, including cancelled ones with a status badge: date tile, game, title link, route, absolute start time with timezone and server. The pill and cards share one `/public/events?period=upcoming&limit=3` read; with no events the pill disappears and the section explains that none are scheduled. Read failures keep the existing translated error and retry. Participant lists are never shown.
- **Stats strip.** Shown under the hero actions only after a valid `GET /api/v1/public/company-stats` response, fetched without cookies (`credentials: "omit"`), no retry, 60 s stale time. Values are exact and unrounded: active members, and for an available month accepted trips, distance on accepted trips in km and the games present, with the month and reporting timezone as a caption. An unavailable month shows only active members; loading, any error status, malformed data, timeout or network failure render nothing, so unavailable is never shown as zero. The strip appears after load and shifts the content below it.
- **Events, ranks and company facts.** The nine event formats, nine rank names and the company history are owner-approved presentation copy. The rank ladder does not change qualification: every member still starts as a Trainee in each game, as the ladder note and the third join step say. The cab chips describe the screenshot.
- **Compact form.** Presentation only: Steam, games and introduction span the card, other fields use two columns when the card is at least 480px wide, the introduction is a full-width textarea and the submit button spans the fields. Field order, labels, validation, submission, retry, privacy and focus behaviour are unchanged.

Motion exists only under `prefers-reduced-motion: no-preference` once the client sets `data-motion` to `running` or `paused`. To meet WCAG 2.2.2, the "Pause animation" toggle (`aria-pressed`) at the end of the hero actions pauses the video, the cab drift and glare and the pulses, and replaces the countdown with the absolute start time. The state is not persisted. Under reduced motion nothing animates and no video is requested; a live switch to reduced motion tears the video down. The toggle remains under reduced motion only while the public list contains a scheduled convoy.

## Submission and recovery

The form collects nickname, invitation email, Steam profile URL and at least one ETS2/ATS choice. Discord and introduction are optional; blank optional fields are omitted. Client technical validation uses generated contract bounds/patterns with the backend's supported Steam URL/mailbox/text constraints. Server validation is authoritative. No provider ownership check is claimed.

A user action obtains same-origin CSRF, then sends one JSON POST to `/api/v1/public/applications` with credentials, a UUID idempotency key and RU/EN `Accept-Language`. Strict success-envelope checks use the generated DTO and runtime-schema bounds/patterns. Only a validated 201 produces the generic acknowledgement. New, duplicate and existing-identity receipts have the same message; receipt IDs, application statuses and email existence are never displayed or looked up.

While pending, controls prevent concurrent accidental submission. A bounded timeout, network failure or malformed result remains uncertain. A manual retry with unchanged normalized form data uses the same payload, key and original command locale (`Accept-Language`), even after changing the interface language. The backend fingerprints the locale with the input. Feedback follows the currently selected interface language. Changed data gets a new key, captures the current command locale and shows an explicit warning that the previous submission might have been saved. There is no automatic mutation retry or mock fallback. CSRF is refreshed on each user retry. A response that rejects the submission preserves input and shows a translated 422/403/409/429/503 message; disabled/unmounted API routes show unavailable. Numeric Retry-After values are bounded to one hour for feedback and submission cooldown; malformed values show generic wait advice. No business eligibility limit is inferred from abuse controls.

Form data, CSRF and receipts live only in component/request memory. They are not put in URLs, browser storage, metadata, analytics or diagnostic logs. Accepted receipt confirmation promises neither membership nor inbox delivery. Staff review, seven-day invitations and native identity behavior remain owned by [VTC-015](admissions.md); live admissions remains disabled by default and requires its separate activation process.

## Verification

`test/unit/landing.test.ts` covers scenario 6 field rules, approved wire-schema fixtures, response validation, safe errors and stable retry keys. `test/unit/landing-live.test.ts` covers RU/EN content parity, the R7d slogan, event formats, ranks, the Trainee start and the six community links, the next-convoy choice, countdown formatting, the card date tile and the anonymous stats read and its exact presentation, including unavailable and zero months and safe failures. `test/unit/landing-video.test.ts` covers the crossfade loop with fake layers and timers: seeking before the first play, swapping only in the last 0.9 s, no double swap, parking the old layer, restarting when the other layer is not ready, unknown durations, pause/resume, rejected play and idempotent teardown. `test/e2e/landing.spec.ts` covers initial HTTP HTML/indexing (including no video in the document), RU/EN rendered phone/tablet/desktop layouts, skip/navigation/menu/form interaction, pending protection, recovery, changed input and rate/unavailable feedback. Live cases that route dated convoy fixtures install a fixed browser clock, so they do not depend on the run date; with fictional events/aggregates they cover the countdown and stable pill name, the start-time refetch, cookie-free stats, hidden/partial/zero stats, empty/cancelled/failed convoy reads, pause and reduced motion, keyboard order, focus, target sizes and the compact form layout. VTC-089 cases add the still painting while the video request is held, one video size per viewport requested only after `load`, aborted or corrupt video keeping the still, stubbed media lifecycle (muted layers, start at 1 s, reveal on `playing`, pause control, hidden tab, teardown), reduced motion without any video request including a live switch, Range/type/cache headers on the built server, the menu focus trap and section focus, pill and slogan geometry against the truck and logo from 360 to 2560px, the no-JavaScript document and a throttled phone profile (1.6 Mbps down, 750 kbps up, 150 ms, CPU 4×) whose media bytes are attached as JSON. Playwright's Chromium cannot decode H.264, so real playback, iOS Safari autoplay and the absence of a visible loop jump remain manual owner checks. Built-document checks also assert the static landing markers and absence of client-only parts. Controlled states intercept only the network boundary and save synthetic screenshots under ignored test output.

`test/unit/public-documents.test.ts` checks malformed shell markers, literal replacement sequences, metadata escaping and actual temporary-file cleanup after success/failure, including cleanup failures. Built-server HTML checks also verify omitted language annotations and the HTTPS Steam destination.

The separate rendered-form integration submits through the real built VTC-015 API and isolated MySQL/local-mail harness. It verifies 201, identical safe duplicate confirmation, absence of an authenticated session and anonymous staff-read denial. A committed response is deliberately withheld from the browser, then an unchanged retry after switching RU/EN must recover the real 201 using the original payload, key and command locale. Real HTTP material is never traced or captured. Existing API-domain tests continue to own review/redemption/security/concurrency evidence. Readiness journeys retain their real MySQL check at `/status`.

Run `node scripts/test-ci.mjs` for the isolated full candidate suite and `node deploy/development/test.mjs` for local production-packaging rehearsal. Neither command activates admissions, sends real email, deploys the site or establishes production acceptance. Visual captures contain only synthetic public states and must be reviewed before publication.

VTC-017 replaces the login boundary with [account lifecycle screens](account.md); public landing and admissions retain their separate ownership.
