## Shared UI-state fixtures

All screens render loading/skeleton state while their request is pending and disable duplicate commands without losing user input. Loading has no HTTP response fixture. Lists use their `:empty` fixture. Reuse the common error envelope from `listTrips:error-403`, `getTrip:error-404`, `decideTrip:error-409`, `pollNotifications:error-401`, `pollNotifications:rate_limited`, `submitManualTrip:invalid_payload` and `getMe:error-503`, adapting only route-local presentation. A 403 must never fall back to stale privileged data; a revoked session clears private query caches.

Dedicated examples include `decideTrip:self_review_forbidden`, `reviseManualTrip:state_conflict`, `issueTelemetryToken:secret_already_issued`, `setEventResponse:declined` and `getCatalogEntity:english-fallback`. Field validation and default error mapping cannot prove the server's business/permission guards; implementing cards need real tests.

Responsiveness and RU/EN states are tested in VTC-012/040. Typed fixtures unblock frontend work, but each UI card retains its live API/integration gates. Early VTC-011 synthetic probes do not implement these journeys, and VTC-005 does not mark any UI or hosted feature complete.
