## Shared UI-state fixtures

All screens render loading/skeleton state while their request is pending and disable duplicate commands without losing user input. Loading has no HTTP response fixture. Lists use their `:empty` fixture. Reuse the common error envelope from `listTrips:error-403`, `getTrip:error-404`, `decideTrip:error-409`, `pollNotifications:error-401`, `pollNotifications:rate_limited`, `submitManualTrip:invalid_payload` and `getMe:error-503`, adapting only route-local presentation. A 403 must never fall back to stale privileged data; a revoked session clears private query caches.

Dedicated examples include `decideTrip:self_review_forbidden`, `reviseManualTrip:state_conflict`, `issueTelemetryToken:secret_already_issued`, `setEventResponse:declined` and `getCatalogEntity:english-fallback`. Field validation and default error mapping cannot prove the server's business/permission guards; implementing cards need real tests.

Responsiveness and RU/EN states are tested in VTC-012/040. Typed fixtures unblock frontend work, but each UI card retains its live API/integration gates. Early VTC-011 synthetic probes do not implement these journeys, and VTC-005 does not mark any UI or hosted feature complete.

VTC-029 implements `EnvelopeTripProposalDecision` for `decideTripProposal`: terminal effective decisions retain the existing `EnvelopeDecision` response; rejection before any terminal effective decision returns the actual rejected `EnvelopeTripProposal` with its immutable `ProposalReview`. Clients distinguish closed `data.outcome` from `data.kind`/`data.state`, refresh the canonical trip using the current ETag, and never infer a rejected trip from a rejected proposal. `Decision` and direct `decideTrip` responses are unchanged.

TripProposal optionally exposes nullable `eventAssociation` with immutable `eventId`, `eventRevisionId` and nullable `attendanceRevisionId`. Event association proposals capture these safe references through Events at creation; later definition/attendance changes do not rewrite proposal readback. Review must display the selected event and retained revisions, then use the current canonical ETag. Current support guards fence obsolete approval. No RSVP reasons or attendance notes are included. Older responses and fixtures without this additive field remain valid.

VTC-038 implements these admin/connection routes using the existing dark account shell and real module HTTP. SourceConnection write operations remain deferred/unmounted. The [administration guide](../../development/administration.md) records ownership, data/security lifetimes and verification/activation boundaries.
