# Data, concurrency and historical decisions

## Values and persistence

VTC-007 implements the audit/value/transaction/migration substrate described in the [persistence contract](../development/persistence.md), with isolated real MySQL tests. The domain transaction boundaries, auth-schema integration and durable jobs below remain requirements for their feature owners. They are not implemented by the substrate.

- Use InnoDB, explicit foreign/unique constraints and strict SQL modes. Development pins MySQL 8.4; exact SQL configuration/patches are tested in VTC-007/008, compared with Hostland in VTC-041. Never substitute MariaDB/SQLite for this evidence.
- Application IDs are lowercase opaque UUIDv4 strings, generated by the server and stored with exact ASCII comparison. Better Auth's ID generator must use the same shape. Catalog IDs are also opaque, scoped by game/kind/map in their records. Provider IDs and the telemetry contract's UUID-shaped identities remain **their existing types**; do not impose application UUID version rules or normalize their case/Unicode.
- Persist UTC as `DATETIME(3)` with explicit UTC serialization/session settings; browser API timestamps are ISO 8601 UTC strings ending `Z`. Telemetry retains its agreed numeric UTC milliseconds and provenance. Date-only analytics boundaries use the configured company timezone, converted once to half-open UTC intervals; unset production reporting timezone returns setup-required rather than guessing.
- Browser API quantities are canonical nonnegative decimal strings in base units: metres, kilograms, litres and fractions. Counts/revisions are bounded safe integers. Money/source uint64/s64 values preserve their frozen string/type/currency semantics. Never sum unknown/different currencies or planned and actual distance.
- Use a documented exact decimal representation for rule/progress arithmetic (candidate `DECIMAL(38,18)` and decimal arithmetic library); reject/escalate out-of-range or precision-losing normalization, never silently round to a different rule outcome. Keep immutable raw source evidence for verification. Display rounding is separate.
- IDs, token hashes, email identity keys and source keys have explicit comparison policies. Opaque keys use binary/exact collation. Email uniqueness follows the chosen auth library's tested normalization; preserve the entered email separately where needed and do not apply Gmail-specific rewriting. Localized labels use separate lookup rules.

## Explicit state axes

| Axis | States / meaning |
| --- | --- |
| Membership | `active`, `inactive`; only active can use member APIs/telemetry. Onboarding is not visible until its creation transaction commits |
| Source game outcome | `open`, `delivered`, `cancelled`, `none`; independent of company credit |
| Recording | `complete`, `partial`, `unknown`; missing facts are not zero or a proven violation |
| Effective company decision | `unassessed`, `pending_review`, `accepted`, `rejected`; an open/unassessed record is not automatically a staff review item. Unknown required terminal facts remain uncredited pending review, including history before qualification |
| Pending correction | Separate proposal/work-item state; an accepted trip stays effectively accepted until staff commits a replacement decision |
| Reconciliation | Canonical trip plus reversible source-link/merge history; a merged alias is not another contribution |
| Event | `scheduled`, `cancelled`, `completed`; public/member visibility is independent |
| RSVP / attendance | RSVP `unanswered`, `participating`, `declined`; actual attendance `unconfirmed`, `attended`, `not_attended` is a separate staff fact |

Each effective decision records normalized fact revision, immutable source/manual revision IDs, rule/catalog revision IDs, qualification assignment period, event conditions/attendance evidence, reason codes, reviewer and attribution timestamps. Never overwrite those inputs in place.

Telemetry uses supported actual start for qualification/rules/progress assignment and actual completion for analytics. Unknown start/historical qualification requires staff resolution, not a current-qualification fallback. Undated manual reports deliberately use confirmation time for qualification/progress/reporting; this is not fabricated gameplay time. Proven rule violations reject; missing/ambiguous required facts need review. Confirmed event attendance plus the event-prescribed load provides the agreed mass/trailer/ADR exception and still counts toward the applicable progress period.

## Transaction boundaries

| Command | Atomic boundary and concurrency guard |
| --- | --- |
| Telemetry receipt | Preserve the [VTC-003](../contracts/telemetry-v1.md) unique event/source-revision/owner scopes; commit immutable source evidence with completed synchronous projection and durable outbox, or a durable processing job, before ACK. Browser idempotency below does not replace telemetry receipts |
| Submit/revise manual report | Lock canonical trip and expected revision, validate ready owner-controlled evidence, insert immutable manual revision + pending review + audit/outbox; same canonical trip on resubmit |
| Review / apply correction / reconcile | Lock canonical trip(s) in sorted ID order, current decision/version and supporting facts; recheck actor != manual author, ownership and expected revisions; write new decision/source links/contribution version + audit/outbox together. Preserve prior accepted outcome while a proposal waits |
| Promote | Lock company/member and per-game assignment/progress; re-evaluate current accepted contributions, write assignment and any global Trainee-to-Driver role change together. Corrections flag promotion review; never auto-demote |
| Change Steam / deactivate / reinstate | Lock current company/member identity; protect current director; atomically bump identity/access epoch as appropriate, change membership/link, revoke tokens/sessions through the identity owner and append audit/outbox. Reinstatement never revives revoked credentials |
| Transfer leadership | Lock singleton company row, current director/challenge and successor; verify serving actor, current verified-email epoch, successor active, bound code/generation, expiry/attempts and expected versions. Update singleton director pointer/derived Director role, retain former Driver membership, consume challenge and append audit/outbox in one commit |
| Event edit / RSVP / attendance | Lock event and target response, enforce revised start-time cutoff using server time, require decline reason, keep attendance separate; write version and reminder invalidation/outbox together |
| Catalog/rule publish | Lock publication pointer, validate reviewed immutable candidate and expected pointer version, commit pointer + audit/outbox. Do not rewrite historical decisions or auto-retire entities from missing sources |

The singleton company `directorUserId` is the authoritative Director grant. Do not duplicate it as an independently writable role row. Non-null pointer + active-member checks protect the last/current director; bootstrap is an explicit operator workflow before member traffic. Role APIs cannot assign/remove Director or modify the serving director's credential channel.

Use one documented lock order for cross-module commands: current company/succession row where needed, actor/target member rows sorted by ID, qualification assignment rows, canonical trips sorted by ID, then decisions/contribution/link rows. Recheck current permissions/epochs through locking reads before effects, not an earlier repeatable-read snapshot. A detected deadlock is a bounded whole-command retry after rollback; network effects remain outside the transaction.

The identity owner must not pretend a library API that uses its own connection participates in an outer Drizzle transaction. Invitation provisioning uses the owned auth-schema repository below, on the exact domain transaction connection. Other auth-table changes must preserve equivalent atomicity or an explicit reviewed workflow with an immediate authoritative access gate. Disable session cookie caching for authorization decisions; check current membership/access epoch on every protected request and before side effects.

## Atomic invitation provisioning across the auth-library boundary

1. Validate the password through the configured auth policy and compute its hash using the **same configured Better Auth hasher** before acquiring database locks. Allocate server IDs; keep the password/hash out of logs, outbox and ordinary idempotency replies. Do not enqueue a plaintext password for later provisioning.
2. Begin the domain transaction, lock the approved unexpired seven-day invitation/current generation, reserve/validate the idempotency key, and recheck its application/email. Reject an unrelated existing identity rather than adopting it by email. A concurrent reissue/consumption must make the old generation fail.
3. Identity's private repository inserts the version-pinned Better Auth user and credential-account schema on the supplied transaction connection; no external `signUpEmail` call or second pool transaction is permitted. Insert active membership and initial per-game assignments/member roles, consume the invitation, append audit/outbox and record the ordinary result **in that same commit**. The credential hash is stored only in the auth credential record. Initial invite possession does not falsely mark a manually delivered invitation's email as verified.
4. Return 201 only after commit, with no automatic session/cookies. The member signs in through the application facade. Failure before commit rolls back **all** auth/member/invitation writes; an uncertain/lost HTTP response is retried with the same key and returns the same safe result. No durable provisioning saga/orphan is required. Auth schema upgrades must preserve this integration contract through reviewed migrations and real sign-in tests.

VTC-013/015 must prove this workflow using real MySQL and the selected auth adapter: its prepared hash/account mapping must be readable by normal library sign-in, and two redeemers, rollback after auth inserts, reissue races and no automatic session issuance must pass. This specification does not claim those DB tests have run or that Better Auth's own public signup automatically joins a domain transaction. If the pinned library cannot support the owned schema/hasher boundary, revise this ADR before implementing a non-atomic fallback.

The one-VTC membership model does not require a company FK before bootstrap: create the initial identity/member and then the singleton company row pointing to that active director in one bootstrap transaction, before traffic is enabled. Avoid circular non-null company/member FKs. Enforce one company row with a singleton key and retain an opaque company ID for telemetry binding; exactly-one-director is required after bootstrap.

## Durable jobs and read projections

Jobs use non-null unique effect keys, bounded batches, explicit transaction context and committed leases (`leaseToken`, `leaseUntil`, attempts/next attempt). Claim via a tested `FOR UPDATE SKIP LOCKED` strategy or equivalent atomic conditional update; release the transaction before network I/O. Completion requires the same lease token. Retry transient deadlocks with a bounded command retry, never blindly repeat a non-idempotent external effect.

Outbox delivery is at-least-once. Domain effects use event ID + consumer unique keys and aggregate/contribution versions; an older event cannot regress a trip or double-count a merge. Trips owns one current authoritative contribution per canonical trip, with explicit assignment-period attribution; the decision coordinator replaces it atomically with the effective decision. Analytics/progress projections can be rebuilt from that register. Compute promotion eligibility from current contributions under lock, not solely an eventually consistent chart. Notification recipients are rechecked on delivery/read; a removed recipient does not inherit stale access.

Reminders are keyed by event revision/member/reminder kind; edit/cancel/RSVP changes invalidate stale generations. An unanswered/declined member receives no attendee reminder. Late initial telemetry is history, not live activity; preserve the telemetry freshness rules. Minute CLI work must handle dependent stages within its budget or surface additional delay; approximately 90 seconds is a healthy-operation target, not an unconditional SLA.

## Migrations and recovery

Drizzle schema generation is owned and serialized in VTC-007. Review SQL, constraint/collation lengths, MySQL lack of generic `RETURNING`, unique keys involving NULL, and implicit DDL commits. Insert with application-generated IDs and select by those IDs; do not depend on PostgreSQL partial indexes or `ON CONFLICT` semantics. A rollback of DML does not roll back DDL. Use compatible additive migrations, forward repair and tested consistent database/evidence export/restore. VTC-008 tests real MySQL concurrency; VTC-041 tests the final host before cutover.


The [VTC-021 implementation](../development/jobs.md) now supplies immutable safe events, queue leases, local effect receipts and a separately supervised bounded minute CLI. Membership/audit/access-event writes share the existing UnitOfWork. Local effects/chained enqueue/completion are atomic and token/expiry fenced; COMMIT uncertainty ends a pass without blind replay. No downstream access-event effect, mail, trip projection or hosted scheduler acceptance is implied.

VTC-022 [source/trip writes](../development/trips.md) share the caller transaction with closed safe source/lifecycle/fact events. Current eligibility is locked before source identity/canonical state; restrictive source/fact/history references and permanent uniqueness survive raw payload expiry. Explicit coordinator attachment checks same owner/game/current version and never sums provider metrics. Raw expiry locks/rechecks canonical review state and payload policy/holds; no scheduler or numeric raw TTL is supplied.


VTC-025 [retention](../development/manual-reports.md#upload-and-deletion-recovery) discovers all historical references, takes sorted canonical-trip locks in bounded batches, then the evidence lock and rechecks discovery. A change releases/retries. Eligibility commits irreversible deleting generation plus durable job; attach/reopen/resubmit loses with retryable503. Filesystem decode/read/delete stays outside row locks. Structured history survives image expiry.
VTC-028 now implements the [qualification transaction boundaries](../development/qualifications.md). Current company/sorted-member locks serialize publication, promotion, lifecycle and contribution corrections; member/game state precedes sorted canonical/contribution locks. Promotion proofs retain the requirements/totals used at confirmation. Replacements re-evaluate affected old/new proofs without changing assigned qualifications. Manual confirmation is explicit decision time, while unknown telemetry history remains unresolved.

VTC-026 [reconciliation transactions](../development/reconciliation.md#commands-locking-and-reversal) prepare company/current member/qualification state before canonical group rows, then source/reconciliation/contribution state. Original source/report/fact identities remain immutable. Group membership, reversible history, monotonic credit replacement, permanent receipt, audit and safe correction outbox share the transaction. Dependent reversals and obsolete reviewed projections conflict; COMMIT uncertainty is resolved by explicit durable receipt replay.

VTC-029 [decision transactions](../development/trip-decisions.md#browser-operations-and-concurrency) combine current group/self-review/support guards, immutable adjudication, effective fact/contribution replacement, promotion-proof checks, evidence retention, audit/outbox and permanent receipt. Supporting history/event changes require fresh review; confirmed results freeze while proposals wait. Staff telemetry timing has explicit resolution provenance; manual confirmation remains a decision instant.
